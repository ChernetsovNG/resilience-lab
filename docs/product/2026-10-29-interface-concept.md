# Resilience Lab — UX-аудит и целевая схема интерфейса

Дата: 2026-10-29\
Статус: согласовано\
Связанные документы: [продуктовое видение](2026-10-27-product-vision.md) (§4 принципы, §5.5 интерфейс), [дизайн этапа 1](../superpowers/specs/2026-10-27-stage-1-design.md) (§6 UI), [план-контракт T4](../superpowers/plans/2026-10-28-stage-1-track-t4-web-results.md).

Дорожки T3 и T4 дали интерфейсу всё, что требует критерий этапа 1: редактор, варианты, проверку, оценку, прогон, сводку, вывод, Timeline, результаты на схеме, воспроизведение и Map. Каждую возможность делали отдельной задачей, и каждая добавила свою полосу, карточку или вкладку. По отдельности они работают по контракту, но вместе плохо складываются в один сценарий. Этот документ фиксирует аудит сквозного сценария и предлагает целостную схему интерфейса, к которой ведут следующие задачи. Он не меняет модельную семантику, а API только расширяет (§4.9).

## 1. Рамка аудита

- **Сценарий** — критерий этапа 1 на демо retry storm: открыть пример → посмотреть схему и предупреждения → запустить → сравнить варианты → понять, что насытилось первым и почему → посмотреть Timeline и воспроизведение на схеме.
- **Состояние** — `main` на `3116267` (после #131 и #132, без #130), рабочая область — копия `examples/`, окно 1440×900, Chromium.
- **Ориентиры** — интерфейсы зрелых систем моделирования (раздел 2). Это источник проверенных решений, а не образец для копирования: наш пользователь — инженер-программист в браузере, а не инженер-расчётчик в настольном приложении.

## 2. Ориентиры

Изучены справки SimInTech, MATLAB Simulink, AnyLogic, OpenModelica OMEdit и Dymola, Simul8; для графиков времени — Grafana. Ниже — решения, которые повторяются в нескольких системах. Именно повторяемость делает их ориентиром.

| Решение | Где встречается | Что берём |
|---|---|---|
| Команды сгруппированы по фазам «подготовка → запуск → разбор» | вкладка Simulation в Simulink (Prepare, Simulate, Review Results); перспективы Modeling и Plotting в OMEdit; Inputs/Outputs в AnyLogic Cloud | верхняя панель делится на зоны «документ» и «запуск» |
| Один докнутый инспектор следует за выделением, модальных диалогов нет | Property Inspector в Simulink; Properties в AnyLogic | инспектор показывает только выбранное; без выделения — эксперимент |
| Вход и выход элемента разделены | вкладки «Свойства» и «Параметры» окна блока SimInTech; inspection window блока в AnyLogic; результаты объекта в Simul8 | в инспекторе секция результатов элемента рядом с его параметрами |
| После прогона интерфейс сам переходит к результатам | OMEdit переключается в Plotting после успешной симуляции | после Run открываются Выводы |
| Значения прямо на схеме, по желанию, вне документа модели | port value labels в Simulink; счётчики на блоках AnyLogic; подписи из окна блока SimInTech | наложение на схеме с выбором метрики |
| Схема ведёт к графикам | бейдж логирования на линии открывает Simulation Data Inspector; «Создать график» в окне блока SimInTech | выбор узла выбирает его ряды на Timeline |
| Сравнение = baseline и отличия | Compare в Simulation Data Inspector (baseline, compare to, разность); в Experiment Builder Simul8 baseline идёт первой колонкой, у KPI есть значки «лучше/хуже» | в Выводах отличие от baseline и признак значимого различия |
| Неопределённость — обычный формат числа | в Simul8 KPI выводятся нижней границей, средним и верхней границей, по умолчанию 5 прогонов и 95 % | интервал у каждой метрики; при малом числе повторений — явная пометка |
| Одна компактная панель времени | панель управления окна модели AnyLogic; шаги вперёд и назад в Simulink | одна строка контекста с пуском, скоростью и шагом |
| Воспроизведение отделено от расчёта | AnyLogic Cloud получает выходы без анимации; OMEdit анимирует готовый файл результатов | уже так (видение §5.5); сохраняем |
| Общий курсор на всех графиках | shared crosshair в Grafana | уже так; распространяем на схему и инспектор |
| Диагностика: счётчик в строке состояния, список по требованию, переход к элементу | Diagnostic Viewer открывается из строки состояния Simulink; Problems AnyLogic появляется при ошибке; область сообщений SimInTech появляется при новом сообщении | счётчик в строке состояния, автопоказ Проблем при новых ошибках |
| Строка состояния с модельным временем и состоянием проекта | SimInTech: модельное время, скорость счёта, признак изменений, выделение, масштаб | новая строка состояния |
| Запуск и управление временем с клавиатуры | F9, Ctrl+F9, Alt+F9 в SimInTech; Ctrl+T и Ctrl+D в Simulink | Ctrl/Cmd+Enter, пробел, стрелки |

Чего не переносим:

- **Много отдельных окон.** Simulation Data Inspector, Diagnostic Viewer и окно модели AnyLogic в браузере превратились бы в вкладки браузера и потеряли бы общий контекст. У нас один экран и режимы панелей.
- **Конструктор интерфейса эксперимента** (страницы экспериментов AnyLogic, шаблоны дашбордов). Инженеру нужен предсказуемый набор видов, а не сборка своего дашборда; дерево графиков, которое собирает сам пользователь, как в менеджере данных SimInTech, — тоже.
- **Модальные окна настроек расчёта** (Simulation Setup в OMEdit, параметры расчёта в SimInTech). Параметры прогона уже правятся без диалога и остаются так.
- **Скорость расчёта, привязанная к анимации** (real time в AnyLogic и SimInTech). Расчёт идёт без привязки к часам, скорость относится только к воспроизведению.
- **Ribbon с десятками кнопок, свободно перестраиваемые панели и F5 для запуска.** В браузере F5 перезагружает страницу.
- **График как блок на схеме** (блоки «Временной график» в SimInTech, Scope в Simulink). Это черта систем сигнального потока, где к проводу подключают осциллограф; сам MathWorks советует Scope для быстрых проверок, а для основной работы — логирование и Simulation Data Inspector без блоков в модели. У нас график не вычислим и не принадлежит документу модели (принцип 1 видения), а ряды пишутся для всех узлов. Поэтому график прикрепляется к выбранному узлу или связи, а не ставится отдельным блоком.

### 3.2. Сквозные проблемы

1. **Нет общей композиции.** На экране восемь независимых полос: верхняя панель, карточка оценки, полоса наложения, проигрыватель, полоса навигации холста, вкладки вариантов, вкладки результатов и тело панели. Каждая добавлена своей задачей, и ни одна не уступает место другим.
2. **Контекст результатов размазан.** Вариант выбирается вкладкой под схемой, точка сетки — в Summary или Map, повторение — в проигрывателе и отдельно в Timeline, время — в проигрывателе и курсором Timeline. Пользователь не видит в одном месте, на что именно он смотрит.
3. **Инспектор смешивает области действия.** Вариант, элемент и эксперимент делят одну колонку. При этом выходы элемента — его загрузка, очередь, отказы — в инспекторе не показаны вовсе: они есть только мелким шрифтом на узле. Связь в результатах почти пуста: на ней одно число amplification, её потоки (попытки в секунду, повторы, таймауты) нигде не собраны, а попасть щелчком по тонкой линии трудно.
4. **Ответ не на первом месте.** После прогона интерфейс не переходит к ответу, а сам вывод лежит в хвосте таблицы.
5. **Проблемы и состояние без постоянного места.** Счётчик проблем есть только на вкладке; статус задания показан дважды; строки состояния нет.
6. **Пространство распределено статично.** У панели результатов три фиксированных размера, а Timeline и Summary нужна разная высота. Левая колонка пустует.
7. **Клавиатура и контекстные меню почти не используются.** Есть Undo/Redo, копирование и удаление; запуска, паузы, шага времени и контекстного меню на элементе нет.
8. **Тексты для разработчика, а не для пользователя.** В сообщениях коды и JSON-указатели, числа вида `80.0 ms`, размеры в байтах, у метрик служебные имена `dependency admitted ×`.

### 3.3. Что работает и сохраняется

- Каркас из видения §5.5: один экран без прокрутки, холст в центре, палитра слева, инспектор справа, варианты под схемой, результаты внизу.
- Результаты на схеме: цвет загрузки, amplification на связях, значок первого насытившегося узла.
- Детерминированное воспроизведение с перемоткой по окнам, общий курсор с Timeline.
- Полоса отказа на графиках, разрывы в пустых окнах, честные интервалы без обрезания.
- Пометка устаревших результатов при несохранённых правках.

## 4. Целевая схема интерфейса

### 4.1. Принципы

1. **Один контекст результатов.** Вариант, точка, повторение и время образуют одно состояние. Оно показано в одном месте, и его меняет любой вид: вкладка варианта, ячейка Map, строка Summary, ползунок времени. Все виды — схема, инспектор, Summary, Timeline — показывают один и тот же контекст.
2. **Вход и выход элемента рядом.** Как в окне свойств блока SimInTech, где свойства (вход) отделены от параметров (выход): инспектор выбранного элемента показывает его параметры, а после прогона — его результаты в текущем контексте.
3. **У каждой области одна роль.** Верхняя панель — документ и запуск. Левая колонка — что добавить. Холст — схема. Инспектор — выбранное. Панель внизу — анализ. Строка состояния — состояние.
4. **Ответ первым.** После прогона первое, что видит пользователь, — вывод с причиной и сравнение вариантов; детали — по запросу.
5. **Место отдаётся текущей задаче.** Размер панели результатов меняется перетаскиванием и запоминается для каждой вкладки; схема при этом вписывается в оставшееся место. Правка и разбор идут на одном экране, без отдельного режима результатов; для разбора есть компоновка «Анализ» (§4.3).
6. **Тексты на языке инженера.** Сообщение начинается с сути и имени элемента, код и путь вторичны; числа и размеры приведены к привычным единицам.
7. **Связь — такой же объект результатов, как узел.** По связи идут потоки, у неё есть свои метрики, ряды и график; её легко выбрать.
8. **Модель — главный объект.** Пользователь сначала рисует модель системы, а потом задаёт ей вопросы. Эксперимент — производное от модели: вопрос к ней со своими вариантами, прогонами и результатами. Интерфейс открывает модель, а не эксперимент (решение 2026-10-30). Вкладка результатов называется «Выводы» / Findings, потому что вопрос эксперимента в интерфейсе не формулируется.

### 4.3. Области

**Верхняя панель — модель и запуск.** Сразу после названия «Resilience Lab» стоит меню «Файл»: новая модель, новый эксперимент, сохранить как, импорт документов с диска в рабочую область и экспорт документов на диск. Затем выбор модели, рядом — выбор эксперимента этой модели; значок настроек открывает в инспекторе настройки прогона текущего эксперимента; признак изменений, Save, Undo/Redo. Рабочая область остаётся каталогом на сервере, а импорт и экспорт переносят её файлы между ним и компьютером пользователя (§7.4). Справа — группа запуска: Run с меню (Estimate, Resume, Cancel). Оценка открывается всплывающей панелью у кнопки Run и закрывается сама; на холст она не ложится. Состояние backend переезжает в строку состояния.

**Модель и эксперименты** (решение 2026-10-30, принцип 8). Модель — главный объект: верхняя панель открывает модель, холст показывает её схему. Эксперимент — вопрос к модели: варианты, параметры прогона, отказы, перебор, а позже и другие виды экспериментов (исследование #202). У модели может быть несколько экспериментов; у `checkout` это «Сравнение настроек» и «Перебор timeout × attempts».

- **«Новая модель»** открывает пустой холст с подсказкой «Добавьте клиента из палитры». Вместе с ней создаётся эксперимент по умолчанию: один вариант, параметры прогона по умолчанию, 10 повторений. Пользователь о нём не думает, пока не захочет сравнивать варианты; `Run` работает сразу, как только схема проходит проверку.
- **«Новый эксперимент»** — действие внутри модели: ещё один вопрос к той же системе. Новый эксперимент ссылается на текущую модель и раскладку.
- **Выбор эксперимента** — список экспериментов текущей модели рядом с выбором модели. Смена эксперимента не меняет схему, а меняет варианты, настройки прогона и результаты.
- **Слово «эксперимент»** стоит только там, где речь именно о нём: список экспериментов модели и его настройки. Главные подписи и действия говорят о модели.
- Форматы документов не меняются: модель, раскладка и эксперименты уже отдельные файлы, и эксперимент ссылается на модель. Список экспериментов модели строится по этим ссылкам.

**Ход эксперимента** (решение 2026-10-30). Что происходит в эксперименте во времени — нагрузка, отказы, разогрев — видно сразу, а не только в полях инспектора и задним числом на Timeline. Это не «сценарий»: так называются шаги обработки и вызовов сервиса.

- **Полоса хода эксперимента** — сворачиваемая лента под схемой с осью модельного времени от 0 до конца прогона, в виде диаграммы Ганта: зоны разогрева и измерения, кривая интенсивности каждого клиента и по полосе на каждый отказ с целью, видом и интервалом, например «psp · замедление ×6 · 20–40 s». Для клиента с видами запросов лента показывает подписанные профили друг под другом и их сумму. Щелчок по полосе отказа открывает его в инспекторе. После прогона полоса делит курсор времени с Timeline и воспроизведением.
- **Отметки на схеме.** У блока или связи, на которые действует отказ, — значок с подсказкой «замедление ×6, 20–40 s»; щелчок открывает отказ.
- **Условия в Выводах.** Над выводом — одна строка условий прогона: нагрузка и отказы, например «Нагрузка 30/s; отказ: psp замедлен ×6 на 20–40 s».
- Первая версия только показывает. Редактирование мышью — перетаскивание и растягивание полос отказов, правка точек профиля на кривой — появляется вместе с редакторами отказов и профиля нагрузки этапа 2.
- Модель и формат не меняются: отказы и профиль уже лежат в документах.

В разделе «Нагрузка» инспектора клиент переключается между одним профилем и несколькими видами запросов. Каждый вид запроса имеет идентификатор, таблицу точек и график; доступны добавление, удаление и перестановка. Новый вид запроса копирует профиль последнего. При возврате к одному профилю сохраняется их кусочно-линейная сумма. Переименование общего вида запроса обновляет его объявления у всех клиентов, ссылки в сценариях, маршрутах и вариантах открытого эксперимента одной записью Undo. При сохранении обновляются и остальные эксперименты этой модели; их имена видны под идентификатором. Если замена создаст повтор идентификатора, правка или сохранение останавливается с пояснением. Удаление оставляет ссылки для диагностики в «Проблемах»; Undo возвращает вид запроса. На странице варианта список переопределяется целиком. Узел такого клиента показывает сумму интенсивностей в начале прогона и число видов запросов; профиль редактируется в инспекторе.

**Левая колонка — что добавить.** Только палитра — узкая полоса значков шириной около 48 px слева, как в draw.io и AnyLogic. Полоса сверху, как в SimInTech, отняла бы 40–50 px высоты — самого дефицитного места — и не вместила бы дерево и поиск библиотеки этапа 2. У блока значок и подпись при наведении. Блок добавляется перетаскиванием туда, куда его бросили. Одиночный щелчок ничего не вставляет, а открывает карточку блока: описание и ссылку на справку по нему. Двойной щелчок или Enter ставят блок в центр видимой области, — так палитра доступна и с клавиатуры, а случайный щелчок не засоряет схему (пересмотрено 2026-10-29: вставка по одиночному щелчку оказалась неожиданной). Раздела Connections нет: связи не перетаскиваются, а протягиваются от порта, об этом говорит подсказка. На этапе 2 полоса раскрывается в панель библиотеки с деревом и поиском. Обозревателя эксперимента на этапе 1 нет: в примере три варианта и одна сетка, навигировать почти нечего, а смешение областей в инспекторе снимается правилом «что выбрано, то и показано» (см. «Инспектор»). Дерево по образцу менеджера данных SimInTech и обозревателя модели Simulink переходит на этап 2, где у него появляется содержание: иерархия блоков (видение §5.7) и история прогонов.

**Холст — только схема.** Над схемой одна компактная **строка контекста результатов**. Она заменяет карточку оценки, полосу наложения и проигрыватель:
- вариант, точка и повторение — отображение и выбор;
- переключатель «Итог | Время»; в режиме времени — пуск, пауза, скорость, шаги и ползунок;
- что наложить на схему: для узлов — загрузка, очередь, отказы; для связей — попытки в секунду, повторы, amplification; легенда выбранной метрики; «выкл.» снимает наложение;
- кнопка компоновки «Анализ».

До первого прогона и на странице модели строки контекста нет. Кнопки масштаба и миникарта лежат поверх холста в нижнем углу, как в draw.io, а не отдельной полосой под схемой: полоса забирала 56 px высоты.

Сетка холста настраивается: шаг и привязка к сетке включаются и выключаются, как в draw.io. Настройка хранится в браузере, а не в документе.

Во время воспроизведения узел не меняет размер. Пока окно ряда не загружено, узел показывает прежние значения приглушённо, и следующий участок ряда подгружается заранее.

Связь выбирается щелчком по линии с широкой зоной попадания или по её подписи-плашке; выбранная связь подсвечивается вместе с концами. Подписи связей не налезают на линии и узлы.

**Компоновка «Анализ»** — одна кнопка вместо нынешнего «развернуть результаты». Палитра и инспектор сворачиваются, экран делят схема с наложением и панель анализа; строка контекста остаётся над схемой. Повторное нажатие или Esc возвращают обычную компоновку. Так Timeline и схема с общим курсором видны одновременно и крупно; сейчас развёрнутая панель схему прячет. Экран делится по вертикали: схема сверху, примерно 35–40 % высоты, вписана по ширине — цепочка широкая и низкая; панель анализа снизу на всю ширину, чтобы графикам хватало оси времени. Палитра скрыта. Инспектор — узкая правая колонка только с секцией «Результаты» выбранного узла или связи; выбор элемента одновременно переключает Timeline на его ряды. Параметры правятся двойным щелчком на схеме или после выхода из «Анализа».

**Вкладки вариантов — страницы.** Как в draw.io: «+» добавляет вариант, контекстное меню вкладки копирует, переименовывает и удаляет его. Свойства варианта открываются в инспекторе по щелчку на активной вкладке. Вкладка модели отделена от вкладок вариантов, у группы вариантов есть подпись «Варианты», а подсказка объясняет, что вариант — это та же модель с переопределёнными параметрами, и называет число переопределений.

**Страница варианта говорит сама за себя** (решение 2026-10-30: без этого непонятно, что за вариант и чем он отличается). Структура и раскладка на ней только для просмотра, а блоки после прогона окрашены метриками, поэтому сами блоки не делаются прозрачными и не перекрашиваются. Вместо этого:

- **холст целиком** обведён рамкой цвета вариантов, а в его углу — плашка со значком замка: имя варианта, «структура только для просмотра» и число изменений; щелчок по плашке раскрывает список изменений;
- **список изменений** — каждое переопределение одной строкой: элемент, параметр, значение модели и значение варианта, например `middle-to-dependency · Attempts: 3 → 1`; щелчок по строке выбирает элемент и поле в инспекторе. Тот же список — в свойствах варианта в инспекторе;
- **изменённые элементы на схеме** выделены тем же янтарным акцентом, что изменённые поля в инспекторе: рамка блока или подписи связи, а в строке параметров на узле — значение варианта рядом с зачёркнутым значением модели;
- **попытка правки структуры** не молчит: на блоке обычный курсор, а не «рука»; попытка перетащить блок, протянуть связь или добавить блок показывает подсказку «Структура правится на странице Model» со ссылкой на неё.

**Инспектор — только выбранное.** Для элемента — узла или связи — две секции:
- **Параметры** — как сейчас, с описанием поля под ним, а не только в подсказке, и с отметкой переопределения. Здесь же — «Описание» и «Заметки» выбранного блока или связи; на странице варианта они доступны только для чтения;
- **Результаты** — после прогона, в текущем контексте: метрики элемента с 95 % CI, маленькие графики за прогон, ссылка «Показать на Timeline» и допущения типа. У сервиса — загрузка, очередь, отказы, задержка; у связи — по её собственным рядам: отправленные попытки и повторы, доля таймаутов, orphaned work, попытки «в полёте», длительность вызова со стороны вызывающего рядом с timeout и amplification.

У клиента в результатах показаны сохранённые доля успешных, p95, p99, причины отказа и успешные с заглушкой; ниже — виды запросов этого клиента. Эти значения относятся ко всем повторениям, включая просмотр с курсором времени. При выбранном окне у клиента с заглушкой дополнительно показана интенсивность успешных запросов с заглушкой по времени завершения в этом окне. Результат общего для нескольких клиентов вида запроса подписан как суммарный по ним.

Выходы политик появляются в результатах элемента, если соответствующая политика задана хотя бы в одном рассчитанном варианте или точке перебора. У отдельной реплики учитываются её отличия. Таблица реплик добавляет сортируемые столбцы «Выведена», «Не готова» и «Отклонены ограничением» только при соответствующих политиках; значения берутся из сохранённых итогов каждой реплики.

Что выбрано, то и показано: щелчок по элементу — элемент; щелчок по активной вкладке варианта — свойства варианта; щелчок по пустому холсту или пункт «Эксперимент» в верхней панели — эксперимент: параметры прогона, отказы, сетка. Действия над вариантом в инспекторе элемента не показываются. В свойствах варианта есть его «Описание»; оно также видно в подсказке вкладки. Для модели и эксперимента поля «Описание» и «Заметки» находятся в разделе «Описания и заметки» настроек прогона, раздельно для двух документов. Пояснения модели на странице варианта доступны только для чтения. Правка поля завершается при выходе из него одной записью Undo; пустое поле удаляет ключ, непустой текст сохраняет пробелы и переводы строк. Описание блока или связи открывается через «?» рядом с именем на схеме. Заметки остаются в инспекторе.

**Панель анализа.**
- **Выводы** (Findings). Сверху — две фразы: какой вариант имеет лучшую наблюдаемую долю успешных запросов и какой — наименьший p99. При единственном варианте показаны только «Доля успешных запросов: …» и «p99: …», без сравнения. Если интервалы лидера пересекаются с интервалами всех остальных вариантов, фраза начинается с «Явного лучшего нет — разница в пределах разброса», а наблюдаемый лидер и значение указаны в скобках; при нескольких равных лидерах это проверяется для каждого. Равные лидеры перечисляются вместе; пересечение интервалов выбранного уровня обозначается как «разница в пределах разброса», отсутствие интервала — как недоступное сравнение. Единого рейтинга нет: выбор может различаться по двум метрикам. При переборе сводка и подробный вывод явно называют точку сетки. Общий для вариантов первый насытившийся ресурс показывается один раз, различия — отдельными строками. Ниже — подробности варианта активной страницы: что насытилось первым, когда, в скольких повторениях. Одинаковые пути деградации объединены с числом повторений и диапазонами времени; сначала видны три наиболее частых, остальные раскрываются под «Ещё N путей». В компактной таблице варианты стоят в колонках, первым — baseline, метрики — в строках, метрики сервисов — в раскрываемых группах. У остальных вариантов показано отличие от baseline и признак, различаются ли интервалы. Квантили, совпадающие с настроенным таймаутом или дедлайном с учётом погрешности скетча 0,78125 %, получают пометку «совпадает с таймаутом N» или «совпадает с дедлайном N» с источником. Подсказка объясняет возможное совпадение p95 и p99; пометка не утверждает, что таймаут действительно сработал. Пределы берутся из документов выполненного прогона с переопределениями варианта и точки. При числе повторений меньше 5 интервал не скрывается и не обрезается, а показывается приглушённо с пометкой «мало повторений — интервал ненадёжен» и советом увеличить `Replications`: при n = 2 коэффициент Стьюдента равен 12,7, и интервал почти в 13 раз шире, чем при n = 10.
  При нескольких клиентах или видах запросов под входом появляются изначально свёрнутые группы «По клиентам» и «По видам запросов». В них те же показатели с интервалами и отличиями от baseline. Строка «Причины отказа» показывает три ведущие причины и раскрывает полный список для сравнения всех вариантов; без отказов явно написано «нет отказов». Строка «Успешные с заглушкой» видна, если заглушка задана в любом варианте или доля ненулевая. Фразы сравнения остаются по входу в целом. У одиночного клиента без видов запросов и политик прежние строки сохраняются.
- **Timeline** — графики узлов и связей, выбранных на схеме (Ctrl+щелчок добавляет элемент), с короткой легендой. Высота панели для Timeline по умолчанию больше, чем для Выводов.
  Рядом с клиентами можно выбрать объявленные виды запросов и их показатели из каталога клиента: интенсивность исходных, успешных и неуспешных запросов, успешные с заглушкой и задержки. Под графиком интенсивностей видны полосы «breaker открыт», «выведен» и «не готов» для выбранных связей и экземпляров с соответствующими политиками. Насыщенность цвета показывает долю окна; для связи суммарное время размыкания делится на число её копий у реплик вызывающего. Подсказка называет долю и число реплик. Полосы используют общий курсор и показывают состояния каждого сравниваемого варианта отдельно.
- **Map** — ячейка выбирает точку контекста. При нескольких клиентах или видах запросов список «Вход» переключает метрики между входом в целом, клиентом и видом запроса; по умолчанию выбран вход в целом. Сервисные показатели от этого выбора не зависят.
- **Проблемы** — сообщение начинается с сути и имени элемента; код и путь серым; щелчок выбирает элемент и поле. Как область сообщений SimInTech, вкладка открывается сама при появлении новых ошибок.
- **Допущения** — общие допущения и условия прогона. Допущения типа блока дублируются в инспекторе.

Размер панели меняется перетаскиванием разделителя и запоминается для каждой вкладки. Кнопка «свернуть» остаётся, «развернуть» заменяет компоновка «Анализ». Щелчок по вкладке свёрнутой панели раскрывает её на этой вкладке.

**Перебор параметров** (сейчас `Parameter grid`) объясняет себя сам (решение 2026-10-30). Секция называется «Перебор параметров» и начинается строкой смысла: эксперимент прогоняется для каждой комбинации значений, результат — на вкладке Map. Рядом — стоимость: «3 × 3 = 9 точек × 2 варианта × 10 повторений = 180 прогонов». Сказано, что перебор общий для всех вариантов и перекрывает их значения этих параметров. Ось читается фразой: параметр человеческим названием с элементом и значения плашками, описание параметра — в подсказке, а не под каждым значением. Предупреждения линтера по точкам перебора не дублируются по вариантам: одна строка называет значение оси и перечисляет варианты, а не идентификаторы `p0`, `p1`. Перебор больше двух параметров, планы экспериментов и оптимизация — не расширение этой секции, а отдельная тема: типы экспериментов, возможно с отдельной страницей, исследуются отдельно.

**Справка.** У каждого типа блока и связи есть справка: что моделирует блок, его параметры с единицами, значениями по умолчанию и пределами, допущения и выходные метрики с их смыслом. Она открывается из карточки палитры и из инспектора. Источник — каталог API и каталог сообщений web, отдельных страниц документации не появляется. Поля оценки (Estimate) объясняются подсказками там же, где показаны.

**Вид блока на схеме — по типу** (решение 2026-10-31). Блоки различаются силуэтом и значком в шапке; внутри находятся имя, ключевые параметры со встроенной правкой и метрики. Клиент — фигура «Person» нотации [C4](https://c4model.com/): круглая голова диаметром 38 % ширины узла, нижней третью скрытая за телом; верхние углы тела образуют плечи радиусом 25 % ширины, нижние скруглены радиусом 8 px. Содержимое начинается ниже плеч; при нехватке места клиент становится выше. Сервис — карточка со скруглёнными углами; БД — цилиндр с эллиптической крышкой высотой 16 px; пулер — двойная рамка с отступом 6 px; маршрутизатор — круг, вписанный в меньшую сторону узла размером 144 × 144 px. Группа реплик — основная карточка и две задние кромки со смещением 4 и 8 px, метка ×N; стопка прибавляет 8 px к высоте. [Превью](../design/block-shapes.svg) показывают фигуры в трёх размерах; [эталон Person](../design/person.svg) задаёт его пропорции.

Фигура рисуется встроенным SVG позади HTML-содержимого. Контур, область содержимого и порты вычисляются по фактическим размерам узла; порты лежат на видимом контуре. Строки метрик резервируются до прогона, поэтому Run не меняет размер узла. Окраска через `--node-fill` и `--node-stroke`, выделение и отметки переопределений, отказов и насыщения сохраняются для всех типов. Значок в шапке тот же, что в палитре. Тип без собственного вида получает обычную карточку: новые типы, например очередь и кэш, смогут добавить свой силуэт. Рамки и надписи без смысла для модели (например, «sidecar» вокруг двух блоков) относятся к отдельной теме пояснительных элементов холста.

**Подсказки полей — значком «?»** (решение 2026-10-30). Под полем не стоит строка описания: у поля видна короткая подпись, а рядом — маленький значок «?». Окно с полным текстом открывается при наведении, по фокусу с клавиатуры и по щелчку, чтобы работать и без мыши, и на тачпаде; Escape и щелчок вне окна его закрывают. Текст может занимать несколько предложений: что это за величина, на что влияет, в каких единицах. Правило одно для всех мест: параметры блоков и связей в инспекторе, настройки прогона, отказы, поля оценки, переключатели результатов вроде уровня доверия. Подсказка браузера (`title`) остаётся только у кнопок-значков без подписи, где нужно назвать действие, а не объяснить его. Так инспектор остаётся плотным (§4.7), а объяснение — в одном движении от поля.

**Строка состояния** — новая, по образцу SimInTech: состояние задания и прогресс, счётчик ошибок и предупреждений (щелчок открывает Проблемы), время курсора, признак устаревших результатов, состояние backend, масштаб холста.

**Виды запросов у шагов и маршрутов.** Поле «Выполнять для» у шага сценария и «Направлять в <цель маршрута>» у связи `route` выбирает несколько видов запросов, объявленных клиентами модели. Пустой выбор снимает ограничение. На странице варианта эти структурные поля доступны только для просмотра. Удалённый из клиентов вид запроса остаётся выбранным до исправления; ошибка ядра видна у поля. На схеме маршрут показывает один или два вида запросов, для большего числа — первый и число остальных; подсказка перечисляет все. Ошибка об отсутствии маршрута для вида запроса отмечается у маршрутизатора. Модели без видов запросов сохраняют прежний вид, каждая правка отменяется одним Undo.

### 4.4. Поведение

- **После Run** панель анализа открывает вкладку Выводы, если пользователь не переключился сам во время прогона. Наложение на схеме включено, контекст — вариант активной страницы, точка p0, режим «Итог».
- **Выбор элемента** — один для всех видов: щелчок на схеме, в Проблемах или в строке Выводов выбирает элемент; Timeline показывает его ряды, инспектор — его параметры и результаты.
- **Клавиатура.** Ctrl/Cmd+Enter — Run, Ctrl/Cmd+S — Save. На холсте: пробел — пуск и пауза, ←/→ — шаг окна, Esc — выход из режима времени, `?` — список клавиш. Клавиши не перехватываются в полях ввода. F-клавиши не используются: F5 в браузере перезагружает страницу.
- **Контекстное меню элемента:** показать на Timeline, вернуть значение модели (на странице варианта), копировать, удалить.

### 4.5. Язык и расширяемость под i18n

Интерфейс на двух языках — английском и русском (решение 2026-10-29: на родном языке интерфейс проще оценивать). Переводится весь текст, который видит пользователь: подписи и подсказки, Выводы и вывод, Проблемы и сообщения линтера, оценка и её предупреждения, ошибки API и задания, описания и допущения из каталога. Не переводятся только пользовательские данные — содержимое документов, в том числе описания и заметки примеров, — и вывод CLI. Язык по умолчанию берётся из языка браузера: `ru-*` — русский, иначе английский; переключатель — в настройках вида. Английский остаётся основным: на нём пишутся ключи, исходные тексты и тесты.

Перевод следует глоссарию в каталоге сообщений. Термины с устоявшимся русским названием переводятся: таймаут, повтор, попытка, очередь, обработчики, загрузка, дедлайн. Обозначения p50, p95, p99, RPS и CI остаются как есть. Пользовательские данные — идентификаторы элементов, имена вариантов, пути документов — не переводятся.

Чтобы языки добавлялись без переделки:

- **Строки — из каталога сообщений.** Видимый пользователю текст берётся по ключу из каталога (`en` и `ru`, набор ключей у них одинаковый) с подстановкой параметров; строковых литералов в компонентах нет. Библиотеку для этого выбирают в задаче по правилу новых зависимостей; хватает и небольшой своей функции над JSON-каталогами.
- **Числа, единицы, проценты и размеры** форматируются одной функцией с учётом локали (`Intl.NumberFormat`), а не склейкой строк: `80 ms`, `65.7 %`, `800 KiB`.
- **Тексты ядра.** Подписи и описания типов, параметров и допущений приходят из каталога API на английском и служат запасным вариантом; перевод ищется в каталоге сообщений web по идентификаторам типа и параметра. Остальная проза ядра и API сейчас приходит готовым английским `message`: диагностика (`Diagnostic`), ошибки API (`ApiProblem`), предупреждения оценки (`EstimateWarning`) и ошибка задания (`JobView.error`, у неё нет даже кода). Чтобы web показал их на языке интерфейса, у каждого такого сообщения есть стабильный `code` и необязательные структурированные аргументы `args` (расширение API по ADR 0010); у ошибки задания появляются код и аргументы рядом с `error`. Web строит текст по коду и аргументам, при неизвестном коде показывает `message`. `message` остаётся для CLI и старых клиентов. Вывод о насыщении уже строится в web из полей сводки.
- **Раскладка терпит длинные строки:** перевод бывает на треть длиннее английского, поэтому у кнопок и вкладок нет фиксированной ширины под текст.
- **Выбор языка** — настройка браузера, а не документа: документы и артефакты от языка не зависят.

### 4.6. Размеры экрана и адаптивность

Интерфейс рассчитан на настольные экраны: от ноутбука с логической шириной 1280–1440 px до мониторов 2K и 4K. Мобильные устройства не поддерживаются. Правила одни для всех областей:

- **Диапазон.** Поддерживаются окна от 1280×720 до 3840×2160. Ниже 1280 px интерфейс не ломается, но под узкий экран не перестраивается. Страница не прокручивается ни при одном поддерживаемом размере.
- **Холст забирает остаток.** У панелей размеры по умолчанию задаются относительно окна с границами минимума и максимума. Например, ширина инспектора — `clamp(280px, 22vw, 480px)`: около 320 px на 1440 px и 480 px на 2560 px. Холст занимает всё оставшееся место, схема вписывается в него.
- **Размеры меняет пользователь.** Границы «холст — инспектор» и «схема — панель анализа» перетаскиваются мышью и сдвигаются стрелками с клавиатуры, двойной щелчок возвращает размер по умолчанию. Инспектор можно свернуть до узкой полосы и развернуть. Все границы используют один компонент разделителя. Сохранённые размеры хранятся в браузере вне документов и важнее размеров по умолчанию, но ограничиваются текущим окном: если окно стало меньше, панели ужимаются до своих минимумов, а не вытесняют холст.
- **Палитра.** На этапе 1 палитра — полоса значков постоянной ширины, без перетаскивания и сворачивания: при 48 px выигрыш был бы мал. Изменяемая ширина появится на этапе 2, когда полоса раскроется в панель библиотеки.
- **Содержимое следует ширине.** Графики Timeline раскладываются в одну–три колонки по доступной ширине, а не фиксированной сеткой. Таблица сравнения в Findings остаётся без горизонтальной прокрутки при числе вариантов из примера. Длинный текст в верхней панели, строке контекста и строке состояния обрезается многоточием с полным текстом в подсказке, а не переносится на вторую строку.
- **Масштаб.** Размеры шрифтов и отступов задаются в `rem` по шкале §4.7; интерфейс остаётся корректным при масштабе браузера от 90 до 150 %. Кроме масштаба браузера, в настройках вида есть размер текста интерфейса — от 90 до 125 %: он меняет корневой размер шрифта и не трогает масштаб холста (пересмотрено 2026-10-29: размер текста нужен без увеличения всей страницы).
- **Проверка.** Ключевой сквозной сценарий — открыть пример → Run → Findings → Time → Timeline — проверяется E2E на окнах 1280×800, 1440×900 и 1920×1080.

### 4.7. Плотность и приоритет холста

Схема — главная область, остальное её обслуживает. Порядок по важности: холст, затем сводка результатов, затем инспектор, затем служебные полосы. Место и крупность текста распределяются в этом порядке.

Замер 2026-10-29 при окне 1440×900 на `main` после #181: холст занимает 1067×689 px, около 57 % окна, а служебные полосы — 211 px высоты (верхняя панель 50, полоса масштаба 56, вкладки вариантов 41, вкладки результатов 36, строка состояния 28). В инспекторе нет своей шкалы шрифтов: почти весь текст — 16 px по умолчанию браузера, заголовки — 18,7 px, а на узлах — 12,8 px. Высота инспектора — 2028 px, больше двух экранов прокрутки.

Правила:

- **Одна шкала шрифтов для всех панелей**, как в IDE и draw.io: основной текст 13 px (`0.8125rem`), подписи и вторичный текст 12 px, заголовки секций 13–14 px полужирным. Значения браузера по умолчанию в панелях не используются.
- **Компактные элементы управления.** Поля ввода, списки и кнопки в инспекторе — одной высоты, около 24–26 px, подпись поля над ним или слева без лишних отступов.
- **Секции инспектора сворачиваются.** Параметры, параметры прогона, отказы и сетка — раскрываемые группы; состояние раскрытия хранится в браузере.
- **Служебные полосы не растут.** Новая информация идёт в существующие полосы или поверх холста, а не новой полосой; масштаб и миникарта — поверх холста (§4.3).

### 4.8. Графики

**Что есть.** Состояние на 2026-10-29: набор графиков Timeline задан в web — шесть групп (Rates, Latency, Errors, Utilization, Call state, Queue), около 20 метрик, фиксированные порядок и высота 176 px. В «Elements and metrics» выбираются элементы и метрики, но выбор сбрасывается при новом прогоне. Цвет даётся по порядку линии из палитры в 6 цветов, поэтому один элемент на разных графиках бывает разного цвета. Показано одно выбранное повторение. Экспорта, настройки осей, увеличения участка и своих графиков нет.

**Отбор показателей и сравнение (2026-10-31).** «Элементы и показатели» перечисляет только блоки и связи текущей модели с выходами Timeline. У каждого элемента своя группа с названием типа и показателями этого типа, без повторов. По умолчанию включены выбранные на схеме элементы; без выделения — первый сервис или первый элемент с рядами. Основные показатели — первые по порядку каталога в каждой доступной группе графиков. Остальные включаются отдельно для элемента; его выключение скрывает показатели и сохраняет их выбор. При новом выделении на схеме Таймлайн следует за ним. При сравнении основной и второй варианты используют разные наборы цветов, внутри которых цвет различает элементы и показатели. Второй вариант дополнительно показан пунктиром. На графиках задержки и в их легендах основной вариант отмечен круглыми маркерами, второй — квадратными: различие сохраняется при плотных точках, скрывающих пунктир. Легенда, подписи порогов и список сравнения используют названия вариантов; идентификатор подставляется только при отсутствии названия.

Кнопка «Показать на таймлайне» из инспектора реплики открывает её линию и полосы состояния политик, если они есть, вместе со сводной линией группы. Загружаются части рядов выбранной реплики; части других реплик не запрашиваются. Из инспектора группы или обычного элемента кнопка показывает ряды этого элемента.

**Какие бывают величины.** Набор не исчерпывающий. Величины трёх видов:

- **записанные ядром** — базовый набор рядов артефакта по окнам: интенсивности, задержки и квантили, загрузка, очередь, попытки «в полёте», брошенная работа, backoff;
- **производные от записанных** — считаются без изменения ядра: доля успешных и доля таймаутов за окно, коэффициент повторов, amplification окна, сумма по элементам, разница вариантов, накопленные итоги;
- **новые измерения** — требуют изменения ядра: например, ожидание в очереди отдельно от обработки, а на этапе 2 — ожидание соединения в пуле БД, метрики реплик, попадания в кэш.

**Принцип: выходы описывает тип.** Как тип блока уже описывает в каталоге свои параметры, он описывает и выходы: идентификатор ряда, название, единицы и вид величины — интенсивность, уровень, задержка, доля. Timeline, секция «Результаты» инспектора и наложение на схеме строятся из каталога, а не из списка в коде web. Тогда новый блок этапа 2 получает графики без правки web. Это расширение каталога API по ADR 0010; стабильные идентификаторы выходов связаны с ключами исходных полей артефакта через закрытые виды вычисления, формат рядов не меняется. Решение описано в [ADR 0011](../architecture/adr/0011-type-outputs.md).

**Первый уровень — в плане:**

1. **Выходы типов в каталоге** по принципу выше. Ядро, API и web.
2. **Экспорт:** график — PNG и SVG, показанные ряды — CSV с единицами и контекстом в заголовке: вариант, точка, повторение. Для отчётов и ADR.
3. **Чтение графиков:**
   - увеличение участка времени выделением мышью, общее для всех графиков, со сбросом двойным щелчком;
   - логарифмическая шкала Y для интенсивностей и задержек;
   - щелчок по строке легенды скрывает и показывает линию;
   - постоянный цвет: при нескольких элементах цвет закреплён за элементом на всех графиках, метрики различаются стилем линии; при одном элементе цвет закреплён за метрикой; при сравнении наборы цветов вариантов не пересекаются, дополнительно применяются пунктир и маркеры разной формы;
   - выбор элементов и метрик запоминается в браузере для эксперимента и переживает новый прогон.
4. **Разброс по повторениям.** По каждому окну — среднее по повторениям и полоса min–max или интервал доверия; выбранное повторение — линией поверх полосы. Сначала проектирование: либо web грузит ряды всех повторений (растут память кэша и время загрузки), либо ядро пишет в артефакт сводные ряды по повторениям (меняется формат артефакта). Выбор — в отдельной задаче-исследовании с замером на `checkout-grid`.

**Второй уровень — по опыту использования:** производные величины из готового набора формул, без своего редактора; свои наборы графиков — какие графики и в каком порядке — с сохранением в браузере (§6.2, идея наборов «элементы × метрики»).

**Не делаем:** ручной выбор цветов, перетаскивание графиков, свободный редактор формул. Для архитектурных вопросов это много работы при малой отдаче; постоянные цвета и наборы графиков закрывают ту же потребность проще.

### 4.9. Что не меняется

Модельная семантика, документы, контракты T3/T4 и инварианты плана T4. API меняется только расширением: коды и аргументы сообщений (§4.5), выходы типов в каталоге (§4.8). Вид Map, правила вывода и воспроизведение по окнам остаются как есть; кэш рядов меняется, только если так решит исследование разброса по повторениям (§4.8). Меняются раскладка, место элементов управления и тексты.

## 6. Решения и открытые вопросы

### 6.1. Решено при обсуждении

- Правка и разбор на одном экране, для разбора — компоновка «Анализ»: схема сверху, анализ снизу, узкий инспектор с результатами выбранного элемента (§4.3).
- Связь — объект результатов наравне с узлом (принцип 7); график прикрепляется к элементу, блока-графика нет (§2). У связи собственные ряды и итоги уже на этапе 1 (§6.2).
- Палитра — узкая полоса значков слева (§4.3), на этапе 1 постоянной ширины. Блок вставляется перетаскиванием, двойным щелчком или Enter; одиночный щелчок открывает карточку блока.
- Холст — главная область; одна компактная шкала шрифтов для панелей, сворачиваемые секции инспектора, масштаб поверх холста (§4.7).
- Интерфейс адаптивен для настольных экранов от 1280×720 до 4K: инспектор и панель анализа меняют размер перетаскиванием, инспектор сворачивается, размеры по умолчанию относительны (§4.6).
- Обозревателя эксперимента на этапе 1 нет: его заменяет правило «что выбрано, то и показано»; дерево — на этапе 2.
- Ход эксперимента виден: полоса под схемой с нагрузкой, отказами и зонами прогона, отметки отказов на схеме, условия прогона в Выводах (§4.3).
- Модель — главный объект интерфейса, эксперимент — производное от неё: верхняя панель выбирает модель, затем её эксперимент; «Новая модель» открывает пустой холст (принцип 8, §4.3).
- Интерфейс на английском и русском, язык по умолчанию — из браузера, переключатель в настройках вида (§4.5).
- Уровень доверия интервалов выбирается в шапке Выводов рядом с таблицей сравнения вариантов: «Интервалы: 95 %» и общий значок «?» с объяснением (§4.3). В меню «Вид» этого пункта нет. Доступны 80, 90, 95 или 99 %, по умолчанию 95 %. Выбор один на браузер, сохраняется в `localStorage` и действует в Выводах, инспекторе и Map без нового прогона. Web пересчитывает интервал Стьюдента из `mean`, `stdDev` и числа повторений; артефакт по-прежнему хранит `ci95Low` и `ci95High`, подписи интервалов называют выбранный уровень.
- Рядом с полем Seed — кнопка случайного значения в допустимом диапазоне ядра.
- Вид блока на схеме — по типу: силуэт и значок в шапке, тело — общая карточка с параметрами и результатами (§4.3).
- Пояснения к полям — в окне за значком «?» рядом с подписью, а не строкой под полем (§4.3, «Подсказки полей»).
- Графики: выходы описывает тип в каталоге; в плане экспорт, удобство чтения и разброс по повторениям; ручных цветов, перетаскивания и редактора формул нет (§4.8).
- Повторений по умолчанию 10, настраивается полем `Replications`, предупреждение при n < 5 (§5, задача 2).

### 6.2. Пересмотрено: ряды связей на этапе 1

Сначала собственные ряды связей и задержку вызова со стороны вызывающего перенесли на этап 2: на этапе 1 значения связи собирались бы из двух соседних узлов. При постановке задачи 9 решение пересмотрено.

У вызова `call` есть собственное вычислимое состояние: отправленные попытки, попытки «в полёте», обрывы по timeout, orphaned work ниже по цепочке, ожидание backoff и длительность вызова. Retry storm — механизм именно на связи. Из узлов эти величины не восстанавливаются, а без них результаты показывают следствия, а не причину.

Поэтому ряды и итоги связей входят в этап 1 (#157), и формат артефакта меняется один раз: этап 2 переиспользует их для DAG, fan-in и реплик. Показ результатов связи (#156) идёт после #157.

Идеи на этап 2 и позже, подсказанные ориентирами: история прогонов в обозревателе с закреплением прогона для сравнения (Dymola, Simulation Data Inspector); действие «сделать вариантом» на ячейке Map (Simulation Manager в Simulink); «добавить повторения» к готовому прогону, чтобы сузить интервал без пересчёта сделанного (Simul8); быстрая вставка блока по имени двойным щелчком по пустому холсту (Quick Insert в Simulink); сохранённые наборы графиков «элементы × метрики» для больших моделей, вне документа модели (категории менеджера данных SimInTech).

### 7.2. Что осталось и что нашлось

1. **Выводы называют узел, но не причину.** Вывод: «dependency first in 10 of 10 replications; median start 225 ms». Данные о причине уже есть в артефакте после #157. На связи `middle-to-dependency` у baseline 2697 отправленных попыток на 1176 исходных запросов — повторы увеличили поток в 2,3 раза. 11 % попыток брошены по timeout и стали orphaned work. Связь вывода с причиной на связи — главный пробел по принципу 3 «ответ, а не панель графиков».
2. **Результаты элемента далеко в инспекторе.** Секция `Results` идёт после всех параметров: в обычной компоновке до неё около 1140 px прокрутки при высоте инспектора 522 px. Результат выбранной связи легко не заметить.
3. **Пустая панель результатов до первого прогона** занимает 261 px — 29 % высоты окна 900 px — с текстом «Run the experiment to see results».
4. **Сырые параметры правила в Findings.** Строка `Saturation rule: minimumDurationMs = 100; handlerUtilizationThreshold = 0.95; …` — это конфигурация, а не объяснение. Заголовок «Baseline · p0» показывает точку и без сетки.
5. **Смешение сумм и средних в результатах связи.** «Orphaned attempts 232» — сумма за 10 повторений, а рядом стоят средние и интенсивности с той же пометкой «Pooled».
6. **Предупреждения линтера на странице модели не видны на схеме.** Оба предупреждения примера относятся к варианту baseline. Открыв пример, пользователь видит только «Warnings: 2» в строке состояния; значки появляются на странице baseline.
