# Resilience Lab — UX-аудит и целевая схема интерфейса

Дата: 2026-10-29\
Статус: согласовано\
Связанные документы: [продуктовое видение](2026-10-27-product-vision.md) (§4 принципы, §5.5 интерфейс), [дизайн этапа 1](../superpowers/specs/2026-10-27-stage-1-design.md) (§6 UI), [план-контракт T4](../superpowers/plans/2026-10-28-stage-1-track-t4-web-results.md).

Дорожки T3 и T4 дали интерфейсу всё, что требует критерий этапа 1: редактор, варианты, проверку, оценку, прогон, сводку, вывод, Timeline, результаты на схеме, воспроизведение и Map. Каждую возможность делали отдельной задачей, и каждая добавила свою полосу, карточку или вкладку. По отдельности они работают по контракту, но вместе плохо складываются в один сценарий. Этот документ фиксирует аудит сквозного сценария и предлагает целостную схему интерфейса, к которой ведут следующие задачи. Он не меняет модельную семантику, а API только расширяет (§4.6).

## 1. Рамка аудита

- **Сценарий** — критерий этапа 1 на демо retry storm: открыть пример → посмотреть схему и предупреждения → запустить → сравнить варианты → понять, что насытилось первым и почему → посмотреть Timeline и воспроизведение на схеме.
- **Состояние** — `main` на `3116267` (после #131 и #132, без #130), рабочая область — копия `examples/`, окно 1440×900, Chromium.
- **Ориентиры** — интерфейсы зрелых систем моделирования (раздел 2). Это источник проверенных решений, а не образец для копирования: наш пользователь — инженер-программист в браузере, а не инженер-расчётчик в настольном приложении.

## 2. Ориентиры

Изучены справки SimInTech, MATLAB Simulink, AnyLogic, OpenModelica OMEdit и Dymola, Simul8; для графиков времени — Grafana. Ниже — решения, которые повторяются в нескольких системах. Именно повторяемость делает их ориентиром.

| Решение | Где встречается | Что берём |
|---|---|---|
| Команды сгруппированы по фазам «подготовка → запуск → разбор» | вкладка Simulation в Simulink (Prepare, Simulate, Review Results); перспективы Modeling и Plotting в OMEdit; Inputs/Outputs в AnyLogic Cloud | верхняя панель делится на зоны «документ» и «запуск» |
| Один докнутый инспектор следует за выделением, модальных диалогов нет | Property Inspector в Simulink; Properties в AnyLogic | инспектор показывает только выбранное; без выделения — эксперимент |
| Вход и выход элемента разделены | вкладки «Свойства» и «Параметры» окна блока SimInTech; inspection window блока в AnyLogic; результаты объекта в Simul8 | в инспекторе секция результатов элемента рядом с его параметрами |
| После прогона интерфейс сам переходит к результатам | OMEdit переключается в Plotting после успешной симуляции | после Run открывается Ответ |
| Значения прямо на схеме, по желанию, вне документа модели | port value labels в Simulink; счётчики на блоках AnyLogic; подписи из окна блока SimInTech | наложение на схеме с выбором метрики |
| Схема ведёт к графикам | бейдж логирования на линии открывает Simulation Data Inspector; «Создать график» в окне блока SimInTech | выбор узла выбирает его ряды на Timeline |
| Сравнение = baseline и отличия | Compare в Simulation Data Inspector (baseline, compare to, разность); в Experiment Builder Simul8 baseline идёт первой колонкой, у KPI есть значки «лучше/хуже» | в Ответе отличие от baseline и признак значимого различия |
| Неопределённость — обычный формат числа | в Simul8 KPI выводятся нижней границей, средним и верхней границей, по умолчанию 5 прогонов и 95 % | интервал у каждой метрики; при малом числе повторений — явная пометка |
| Одна компактная панель времени | панель управления окна модели AnyLogic; шаги вперёд и назад в Simulink | одна строка контекста с пуском, скоростью и шагом |
| Воспроизведение отделено от расчёта | AnyLogic Cloud получает выходы без анимации; OMEdit анимирует готовый файл результатов | уже так (видение §5.5); сохраняем |
| Общий курсор на всех графиках | shared crosshair в Grafana | уже так; распространяем на схему и инспектор |
| Диагностика: счётчик в строке состояния, список по требованию, переход к элементу | Diagnostic Viewer открывается из строки состояния Simulink; Problems AnyLogic появляется при ошибке; область сообщений SimInTech появляется при новом сообщении | счётчик в строке состояния, автопоказ Проблем при новых ошибках |
| Строка состояния с модельным временем и состоянием проекта | SimInTech: модельное время, скорость счёта, признак изменений, выделение, масштаб | новая строка состояния |
| Запуск и управление временем с клавиатуры | F9, Ctrl+F9, Alt+F9 в SimInTech; Ctrl+T и Ctrl+D в Simulink | Ctrl/Cmd+Enter, пробел, стрелки |

Чего не переносим:

- **Много отдельных окон.** Simulation Data Inspector, Diagnostic Viewer и окно модели AnyLogic в браузере превратились бы в вкладки браузера и потеряли бы общий контекст. У нас один экран и режимы панелей.
- **Конструктор интерфейса эксперимента** (страницы экспериментов AnyLogic, шаблоны дашбордов). Инженеру нужен предсказуемый набор видов, а не сборка своего дашборда; дерево графиков, которое собирает сам пользователь, как в менеджере данных SimInTech, — тоже.
- **Модальные окна настроек расчёта** (Simulation Setup в OMEdit, параметры расчёта в SimInTech). Параметры прогона уже правятся без диалога и остаются так.
- **Скорость расчёта, привязанная к анимации** (real time в AnyLogic и SimInTech). Расчёт идёт без привязки к часам, скорость относится только к воспроизведению.
- **Ribbon с десятками кнопок, свободно перестраиваемые панели и F5 для запуска.** В браузере F5 перезагружает страницу.
- **График как блок на схеме** (блоки «Временной график» в SimInTech, Scope в Simulink). Это черта систем сигнального потока, где к проводу подключают осциллограф; сам MathWorks советует Scope для быстрых проверок, а для основной работы — логирование и Simulation Data Inspector без блоков в модели. У нас график не вычислим и не принадлежит документу модели (принцип 1 видения), а ряды пишутся для всех узлов. Поэтому график прикрепляется к выбранному узлу или связи, а не ставится отдельным блоком.

### 3.1. Сквозной сценарий по шагам

### 3.2. Сквозные проблемы

1. **Нет общей композиции.** На экране восемь независимых полос: верхняя панель, карточка оценки, полоса наложения, проигрыватель, полоса навигации холста, вкладки вариантов, вкладки результатов и тело панели. Каждая добавлена своей задачей, и ни одна не уступает место другим.
2. **Контекст результатов размазан.** Вариант выбирается вкладкой под схемой, точка сетки — в Summary или Map, повторение — в проигрывателе и отдельно в Timeline, время — в проигрывателе и курсором Timeline. Пользователь не видит в одном месте, на что именно он смотрит.
3. **Инспектор смешивает области действия.** Вариант, элемент и эксперимент делят одну колонку. При этом выходы элемента — его загрузка, очередь, отказы — в инспекторе не показаны вовсе: они есть только мелким шрифтом на узле. Связь в результатах почти пуста: на ней одно число amplification, её потоки (попытки в секунду, повторы, таймауты) нигде не собраны, а попасть щелчком по тонкой линии трудно.
4. **Ответ не на первом месте.** После прогона интерфейс не переходит к ответу, а сам вывод лежит в хвосте таблицы.
5. **Проблемы и состояние без постоянного места.** Счётчик проблем есть только на вкладке; статус задания показан дважды; строки состояния нет.
6. **Пространство распределено статично.** У панели результатов три фиксированных размера, а Timeline и Summary нужна разная высота. Левая колонка пустует.
7. **Клавиатура и контекстные меню почти не используются.** Есть Undo/Redo, копирование и удаление; запуска, паузы, шага времени и контекстного меню на элементе нет.
8. **Тексты для разработчика, а не для пользователя.** В сообщениях коды и JSON-указатели, числа вида `80.0 ms`, размеры в байтах, у метрик служебные имена `dependency admitted ×`.

### 3.3. Что работает и сохраняется

- Каркас из видения §5.5: один экран без прокрутки, холст в центре, палитра слева, инспектор справа, варианты под схемой, результаты внизу.
- Результаты на схеме: цвет загрузки, amplification на связях, значок первого насытившегося узла.
- Детерминированное воспроизведение с перемоткой по окнам, общий курсор с Timeline.
- Полоса отказа на графиках, разрывы в пустых окнах, честные интервалы без обрезания.
- Пометка устаревших результатов при несохранённых правках.

## 4. Целевая схема интерфейса

### 4.1. Принципы

1. **Один контекст результатов.** Вариант, точка, повторение и время образуют одно состояние. Оно показано в одном месте, и его меняет любой вид: вкладка варианта, ячейка Map, строка Summary, ползунок времени. Все виды — схема, инспектор, Summary, Timeline — показывают один и тот же контекст.
2. **Вход и выход элемента рядом.** Как в окне свойств блока SimInTech, где свойства (вход) отделены от параметров (выход): инспектор выбранного элемента показывает его параметры, а после прогона — его результаты в текущем контексте.
3. **У каждой области одна роль.** Верхняя панель — документ и запуск. Левая колонка — что добавить. Холст — схема. Инспектор — выбранное. Панель внизу — анализ. Строка состояния — состояние.
4. **Ответ первым.** После прогона первое, что видит пользователь, — вывод с причиной и сравнение вариантов; детали — по запросу.
5. **Место отдаётся текущей задаче.** Размер панели результатов меняется перетаскиванием и запоминается для каждой вкладки; схема при этом вписывается в оставшееся место. Правка и разбор идут на одном экране, без отдельного режима результатов; для разбора есть компоновка «Анализ» (§4.3).
6. **Тексты на языке инженера.** Сообщение начинается с сути и имени элемента, код и путь вторичны; числа и размеры приведены к привычным единицам.
7. **Связь — такой же объект результатов, как узел.** По связи идут потоки, у неё есть свои метрики, ряды и график; её легко выбрать.

### 4.3. Области

**Верхняя панель — документ и запуск.** Выбор эксперимента, пункт «Эксперимент» (открывает его настройки в инспекторе), признак изменений, Save, Undo/Redo. Справа — группа запуска: Run с меню (Estimate, Resume, Cancel). Оценка открывается всплывающей панелью у кнопки Run и закрывается сама; на холст она не ложится. Состояние backend переезжает в строку состояния.

**Левая колонка — что добавить.** Только палитра — узкая полоса значков шириной около 48 px слева, как в draw.io и AnyLogic. Полоса сверху, как в SimInTech, отняла бы 40–50 px высоты — самого дефицитного места — и не вместила бы дерево и поиск библиотеки этапа 2. У блока значок и подпись при наведении; блок добавляется перетаскиванием или щелчком, который ставит его в центр видимой области, — так палитра доступна и с клавиатуры. Раздела Connections нет: связи не перетаскиваются, а протягиваются от порта, об этом говорит подсказка. На этапе 2 полоса раскрывается в панель библиотеки с деревом и поиском. Обозревателя эксперимента на этапе 1 нет: в примере три варианта и одна сетка, навигировать почти нечего, а смешение областей в инспекторе снимается правилом «что выбрано, то и показано» (см. «Инспектор»). Дерево по образцу менеджера данных SimInTech и обозревателя модели Simulink переходит на этап 2, где у него появляется содержание: иерархия блоков (видение §5.7) и история прогонов.

**Холст — только схема.** Над схемой одна компактная **строка контекста результатов**. Она заменяет карточку оценки, полосу наложения и проигрыватель:
- вариант, точка и повторение — отображение и выбор;
- переключатель «Итог | Время»; в режиме времени — пуск, пауза, скорость, шаги и ползунок;
- что наложить на схему: для узлов — загрузка, очередь, отказы; для связей — попытки в секунду, повторы, amplification; легенда выбранной метрики; «выкл.» снимает наложение;
- кнопка компоновки «Анализ».

До первого прогона и на странице модели строки контекста нет. Миникарта и масштаб остаются в полосе под схемой.

Связь выбирается щелчком по линии с широкой зоной попадания или по её подписи-плашке; выбранная связь подсвечивается вместе с концами. Подписи связей не налезают на линии и узлы.

**Компоновка «Анализ»** — одна кнопка вместо нынешнего «развернуть результаты». Палитра и инспектор сворачиваются, экран делят схема с наложением и панель анализа; строка контекста остаётся над схемой. Повторное нажатие или Esc возвращают обычную компоновку. Так Timeline и схема с общим курсором видны одновременно и крупно; сейчас развёрнутая панель схему прячет. Экран делится по вертикали: схема сверху, примерно 35–40 % высоты, вписана по ширине — цепочка широкая и низкая; панель анализа снизу на всю ширину, чтобы графикам хватало оси времени. Палитра скрыта. Инспектор — узкая правая колонка только с секцией «Результаты» выбранного узла или связи; выбор элемента одновременно переключает Timeline на его ряды. Параметры правятся двойным щелчком на схеме или после выхода из «Анализа».

**Вкладки вариантов — страницы.** Как в draw.io: «+» добавляет вариант, контекстное меню вкладки копирует, переименовывает и удаляет его. Свойства варианта открываются в инспекторе по щелчку на активной вкладке.

**Инспектор — только выбранное.** Для элемента — узла или связи — две секции:
- **Параметры** — как сейчас, с описанием поля под ним, а не только в подсказке, и с отметкой переопределения;
- **Результаты** — после прогона, в текущем контексте: метрики элемента с 95 % CI, маленькие графики за прогон, ссылка «Показать на Timeline» и допущения типа. У сервиса — загрузка, очередь, отказы, задержка; у связи — попытки в секунду, повторы, таймауты, отказы очереди на входе вызываемого и amplification.

Что выбрано, то и показано: щелчок по элементу — элемент; щелчок по активной вкладке варианта — свойства варианта; щелчок по пустому холсту или пункт «Эксперимент» в верхней панели — эксперимент: параметры прогона, отказы, сетка. Действия над вариантом в инспекторе элемента не показываются.

**Панель анализа.**
- **Ответ** (сейчас Summary). Сверху — вывод с причиной для варианта активной страницы: что насытилось первым, когда, в скольких повторениях, пути деградации. Ниже — компактное сравнение: варианты в колонках, первым — baseline, метрики в строках, метрики сервисов — раскрываемые группы (продолжение #130). У остальных вариантов — отличие от baseline и признак, различаются ли интервалы. При числе повторений меньше 5 интервал не скрывается и не обрезается, а показывается приглушённо с пометкой «мало повторений — интервал ненадёжен» и советом увеличить `Replications`: при n = 2 коэффициент Стьюдента равен 12,7, и интервал почти в 13 раз шире, чем при n = 10.
- **Timeline** — графики узлов и связей, выбранных на схеме (Ctrl+щелчок добавляет элемент), с короткой легендой. Высота панели для Timeline по умолчанию больше, чем для Ответа.
- **Map** — без изменений по смыслу: ячейка выбирает точку контекста.
- **Проблемы** — сообщение начинается с сути и имени элемента; код и путь серым; щелчок выбирает элемент и поле. Как область сообщений SimInTech, вкладка открывается сама при появлении новых ошибок.
- **Допущения** — общие допущения и условия прогона. Допущения типа блока дублируются в инспекторе.

Размер панели меняется перетаскиванием разделителя и запоминается для каждой вкладки. Кнопка «свернуть» остаётся, «развернуть» заменяет компоновка «Анализ».

**Строка состояния** — новая, по образцу SimInTech: состояние задания и прогресс, счётчик ошибок и предупреждений (щелчок открывает Проблемы), время курсора, признак устаревших результатов, состояние backend, масштаб холста.

### 4.4. Поведение

- **После Run** панель анализа открывает вкладку Ответ, если пользователь не переключился сам во время прогона. Наложение на схеме включено, контекст — вариант активной страницы, точка p0, режим «Итог».
- **Выбор элемента** — один для всех видов: щелчок на схеме, в Проблемах или в строке Ответа выбирает элемент; Timeline показывает его ряды, инспектор — его параметры и результаты.
- **Клавиатура.** Ctrl/Cmd+Enter — Run, Ctrl/Cmd+S — Save. На холсте: пробел — пуск и пауза, ←/→ — шаг окна, Esc — выход из режима времени, `?` — список клавиш. Клавиши не перехватываются в полях ввода. F-клавиши не используются: F5 в браузере перезагружает страницу.
- **Контекстное меню элемента:** показать на Timeline, вернуть значение модели (на странице варианта), копировать, удалить.

### 4.5. Язык и расширяемость под i18n

Интерфейс пока на английском: репозиторий публичный, а термины предметной области — timeout, retry, p99, amplification, RPS — английские. Выбор языка добавляется позже без переделки, поэтому уже сейчас:

- **Строки — из каталога сообщений.** Видимый пользователю текст берётся по ключу из каталога (сейчас один, `en`) с подстановкой параметров; строковых литералов в компонентах нет. Библиотеку для этого выбирают в задаче по правилу новых зависимостей; хватает и небольшой своей функции над JSON-каталогами.
- **Числа, единицы, проценты и размеры** форматируются одной функцией с учётом локали (`Intl.NumberFormat`), а не склейкой строк: `80 ms`, `65.7 %`, `800 KiB`.
- **Тексты ядра.** Подписи и описания типов, параметров и допущений приходят из каталога API на английском и служат запасным вариантом; перевод ищется в каталоге сообщений web по идентификаторам типа и параметра. Диагностика сейчас передаёт готовый английский `message`; чтобы web мог показать её на другом языке, `Diagnostic` получает необязательные структурированные аргументы рядом со стабильным `code` (расширение API по ADR 0010), а web строит текст по коду и аргументам, при неизвестном коде — показывает `message`. Вывод о насыщении уже строится в web из полей сводки.
- **Раскладка терпит длинные строки:** перевод бывает на треть длиннее английского, поэтому у кнопок и вкладок нет фиксированной ширины под текст.
- **Выбор языка** будет настройкой браузера, а не документа: документы и артефакты от языка не зависят.

### 4.6. Что не меняется

Модельная семантика, документы, контракты T3/T4 и инварианты плана T4. API меняется только расширением: аргументы диагностики (§4.5). Вид Map, правила вывода, кэш рядов и воспроизведение по окнам остаются как есть. Меняются раскладка, место элементов управления и тексты.

## 5. Путь к целевой схеме

Задачи идут волнами; задачи внутри волны независимы. #130 (ширина Summary, карточка оценки, единицы размеров, Run при сбое оценки) в работе и согласуется с этой схемой: дальнейшие задачи опираются на её результат.

**Подготовка** (после #130):

0. **Каталог сообщений и форматирование.** Функция строк по ключу и каталог `en`, единое форматирование чисел и единиц; существующие строки переносятся в каталог. Следующие задачи пишут тексты сразу через него.

**Волна 1 — ответ и состояние:**

1. **Ответ первым.** Вкладка Summary становится «Ответом»: вывод сверху, компактное сравнение ниже, переход на неё после Run, пометка «мало повторений» вместо абсурдного интервала.
2. **Достоверность по умолчанию.** Пример `retry-storm` — 10 повторений вместо 2; предупреждение линтера ядра при `replications` < 5 (видно до запуска в UI и CLI); сверка E2E, которые опираются на числа примера. `replications` остаётся обязательным полем документа эксперимента: число повторений задаётся явно, прогон воспроизводится без скрытых умолчаний; шаблон будущей команды «новый эксперимент» берёт 10.
3. **Строка состояния и Проблемы.** Новая строка состояния; статус задания и backend переезжают в неё; читаемые сообщения Проблем; автопоказ при новых ошибках. Если для текста нужны аргументы диагностики — расширение `Diagnostic` по §4.5.

**Волна 2 — пространство:**

4. **Строка контекста результатов.** Одна строка над схемой вместо полосы наложения и проигрывателя; оценка — всплывающей панелью у Run; один выход из режима времени для схемы и Timeline.
5. **Изменяемая высота панели анализа и компоновка «Анализ».** Разделитель, размер по вкладкам; «Анализ» вместо развёрнутой панели, схема остаётся видна.
6. **Палитра-полоса.** Узкая полоса значков, добавление щелчком и перетаскиванием, подсказка о связях вместо раздела Connections.

**Волна 3 — структура:**

7. **Инспектор только выбранного.** Правило «что выбрано, то и показано»; пункт «Эксперимент» в верхней панели; варианты и настройки эксперимента уходят из инспектора элемента; действия над вариантом — в «+» и контекстном меню вкладки.
8. **Результаты элемента в инспекторе, связь как объект результатов.** Секция «Результаты» для узла и связи в текущем контексте, допущения типа; ряды связи на Timeline; метрики связей в наложении; удобный выбор связи.

**Волна 4 — скорость работы:**

9. **Клавиатура и контекстные меню** по §4.4.

Каждая задача проверяется на сквозном сценарии из §1 скриншотами до и после в ветке `pr-assets`. После волны 2 стоит повторить этот аудит.

## 6. Решения и открытые вопросы

### 6.1. Решено при обсуждении

- Правка и разбор на одном экране, для разбора — компоновка «Анализ»: схема сверху, анализ снизу, узкий инспектор с результатами выбранного элемента (§4.3).
- Связь — объект результатов наравне с узлом (принцип 7); график прикрепляется к элементу, блока-графика нет (§2).
- Палитра — узкая полоса значков слева (§4.3).
- Обозревателя эксперимента на этапе 1 нет: его заменяет правило «что выбрано, то и показано»; дерево — на этапе 2.
- Интерфейс пока на английском, дизайн расширяем под i18n (§4.5).
- Повторений по умолчанию 10, настраивается полем `Replications`, предупреждение при n < 5 (§5, задача 2).

### 6.2. Перенесено на этап 2

- **Ряды связей в артефакте.** Сейчас ряды пишутся по узлам, а значения связи собираются из двух соседних узлов: в линейной цепочке это однозначно. При DAG, fan-in и репликах за балансировщиком ряды узла по связям не раскладываются, и связям понадобятся собственные ряды: попытки, повторы, таймауты и задержка вызова. Это изменение ядра и формата артефакта; его нужно заложить в дизайн этапа 2.
- **Задержка вызова со стороны вызывающего.** `latency` сервиса — время внутри него; задержки, которую видит вызывающий (сеть, очередь, обработка, обрыв по timeout), в рядах нет. Она добавляется на этапе 2 вместе с рядами связей, чтобы формат артефакта сменился один раз. На этапе 1 связь показывает попытки, повторы, таймауты и amplification без распределения длительности вызова.

Идеи на этап 2 и позже, подсказанные ориентирами: история прогонов в обозревателе с закреплением прогона для сравнения (Dymola, Simulation Data Inspector); действие «сделать вариантом» на ячейке Map (Simulation Manager в Simulink); «добавить повторения» к готовому прогону, чтобы сузить интервал без пересчёта сделанного (Simul8); быстрая вставка блока по имени двойным щелчком по пустому холсту (Quick Insert в Simulink); сохранённые наборы графиков «элементы × метрики» для больших моделей, вне документа модели (категории менеджера данных SimInTech).
