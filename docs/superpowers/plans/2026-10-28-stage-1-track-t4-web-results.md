## Общие инварианты

1. **Результаты только читаются.** Просмотр, выбор точки, повторения и курсора, воспроизведение не меняют документы и не попадают в историю undo/redo (дизайн §6.2).
2. **Данные — из API прогона.** Сначала сводка, ряды — по выбору варианта, точки и повторения (ADR 0008, п. 7). Web показывает метрики артефакта и не выдумывает других. Новые поля сервера — аддитивно (ADR 0010), с пересозданием `apps/server/openapi.json` и TS-типов.
3. **Формулы — из формата артефакта.** Загрузка, средняя очередь, интенсивности и задержки считаются по `docs/results-format.md`. Квантили — по профилю S5 с интерполяцией KSL, среднее — из count и sum, p99 не усредняется.
4. **Детерминизм кадра.** Всё, что показано для момента времени, — функция прогона, варианта, точки, повторения и номера окна. Часы браузера только сдвигают номер окна при воспроизведении.
5. **Общий контекст результатов.** Страница варианта под холстом выбирает вариант. Точка сетки, повторение и курсор времени выбираются один раз и действуют на Summary, Timeline, схему и Map одновременно. На странице модели результаты на схеме не показываются: модель — не прогон.
6. **Устаревшие результаты видны.** Если модель или эксперимент, включая несохранённые правки, отличаются от тех, с которыми запущен прогон, панель и схема помечают результаты как относящиеся к прежней версии. Элементы схемы, которых нет в прогоне, значений не получают.
7. **Бюджеты ADR 0008.** Распаковка и разбор частей — в Web Worker. Часть отдаётся UI целиком, она не больше 4 МиБ до сжатия. Кэш декодированных данных — порядка 64 МиБ, с вытеснением. Для экрана ряды прореживаются с сохранением минимумов, максимумов и переходов.
8. **Экран без прокрутки**, светлая тема, привычные единицы — RPS, ms, % (видение §5.5).
9. **Зависимости.** Для графиков в `web/package.json` уже есть `recharts`. Другая библиотека или новая зависимость — только с обоснованием в issue (`AGENTS.md`).
10. **Тесты.** Unit — для вычислений и состояния; E2E — по сценариям приёмки на копии рабочей области (дизайн §8); `npm run api:check` проходит.

## T4.1 Панель результатов, допущения, отмена

**Входит.** #12: панель с вкладками Summary, Assumptions и Problems; Summary по вариантам и точкам; выбор точки сетки; допущения модели из каталога и условия прогона из манифеста; отмена задания из UI.

**Не входит.** Вкладки Timeline (T4.3) и Map (T4.8), текст вывода (T4.5), оценка и досчёт (T4.7). Открытие прошлых прогонов из `GET /runs` — отдельной задачей, если понадобится.

**Контракт.**
- Панель бывает свёрнутой (видны вкладки и статус задания), обычной и развёрнутой на высоту рабочей области. Её состояние не попадает в документы. Страница не прокручивается ни в одном состоянии.
- Summary по каждой паре «вариант, точка»: success rate, p95 и p99, amplification и загрузка сервисов. Средние по повторениям — с 95 % CI, как сейчас. Загрузка — `busyHandlerTimeMs / handlerCapacityTimeMs` из `totals` по пулу повторений, так и подписана. Вариант активной страницы выделен.
- У прогона с сеткой есть выбор точки: идентификатор и координаты в единицах документа. Выбор задаёт точку контекста результатов (инвариант 5). Без сетки — `p0`, выбора нет.
- Допущения хранятся в каталоге ядра, а не в web. `Catalog` и `TypeDescriptor` аддитивно получают списки допущений на английском, как `description`. Источник текстов — семантика проектного дизайна MVP (§8): удержание обработчика на время вызова и backoff, orphaned work, отбрасывание поздних ответов, отсутствие отмены по цепочке. Из дизайна этапа 1 (§4.3–4.6) — когорта измерения, окна по времени событий, погрешность скетча и доверительные интервалы Стьюдента без обрезания. `GET /api/v1/catalog` отдаёт их без отдельной ручки.
- Вкладка Assumptions показывает общие допущения, допущения типов блоков модели прогона и условия прогона из `GET /runs/{id}/manifest`: повторения, seed, разогрев, измеряемый интервал, окно рядов, профиль скетча, версии приложения и KSL.
- Пометка устаревших результатов (инвариант 6) появляется здесь, для Summary и Assumptions; Problems работает как сейчас.
- Пока задание в очереди или выполняется, рядом с Run есть Cancel: `POST /jobs/{id}/cancel`. До остановки виден признак `cancelRequested`. После `CANCELLED` панель сообщает, что прогон не закончен и сводки нет, а Run снова доступен. Ответ 409 `JOB_FINISHED` не ошибка для пользователя: показывается итоговый статус задания.

**Приёмка.**
- Ядро и сервер: у каждого типа каталога этапа 1 есть допущения; ответ каталога сверяется с OpenAPI.
- Unit: строки Summary с CI, единицами и загрузкой; выбор точки; условия прогона из манифеста.
- E2E: прогон retry-storm → Summary по двум вариантам и Assumptions с условиями прогона; панель сворачивается и разворачивается без прокрутки страницы; отмена длинного прогона на копии рабочей области → статус отмены, Run доступен.

## T4.2 Загрузка рядов и метрики окон

**Входит.** #102: слой данных для T4.3–T4.8. Сюда входят чтение индекса и частей через ручки T2.1, разбор в Web Worker, скетчи по профилю S5 на TypeScript, метрики окон и кэш. Новых компонентов интерфейса нет.

**Не входит.** Графики и прореживание для экрана (T4.3), отображение на схеме (T4.4, T4.6), объединение рядов нескольких повторений.

**Контракт.**
- Запрос задаётся прогоном, вариантом, точкой, повторением, набором узлов и диапазоном окон. Результат — метрики по каждому узлу и окну, с `startMs` и `durationMs` окна. Загрузка читает индекс и запрашивает только нужные части.
- Метрики клиента: интенсивности исходных запросов, успехов и неуспехов в секунду; задержка — среднее, p50, p95, p99.
- Метрики сервиса: интенсивности `offeredAttempts`, `admittedAttempts`, `queueRejections`, `successes`, `failures`, `timeouts`, `retries` в секунду; загрузка и средняя очередь по формулам формата; задержка — среднее, p50, p95, p99.
- Amplification окна сервиса — `admittedAttempts` сервиса, делённое на исходные запросы клиентов в том же окне; при нуле запросов — нет значения. Это оконное приближение: попытки окна могут относиться к запросам прошлых окон; описание метрики это оговаривает.
- Пустое окно не имеет среднего и квантилей; загрузка и очередь в нём равны нулю.
- Квантили и среднее вычисляются по профилю `ddsketch-bitwise6-rational-v1`; за основу можно взять реализацию S5. Эталон — часть ряда прогона retry-storm и квантили, вычисленные ядром, — лежит в репозитории. Web-тест сверяет квантили побитно. Команда пересоздания эталона описана в `AGENTS.md`, как для схем и OpenAPI.
- Распаковку делает браузер по `Content-Encoding`. JSON.parse и декодирование скетчей идут в Web Worker, основной поток получает готовые числа. Если `ETag` части не совпадает с `sha256` в индексе, это ошибка загрузки, а не молча принятые данные.
- Запросы, ставшие ненужными после смены выбора, отменяются, их ответы не применяются.
- Кэш хранит данные по прогону, варианту, точке, повторению и части. Объём ограничен оценкой декодированных данных порядка 64 МиБ, давно неиспользуемое вытесняется. Прогоны неизменны, поэтому инвалидации нет.
- 404 `SERIES_NOT_FOUND`, например у незаконченной задачи, — понятное состояние «ряды недоступны», а не сбой интерфейса.

**Приёмка.**
- Unit: метрики окна по формулам формата, включая пустые окна; побитное совпадение квантилей с эталоном ядра; выбор частей по индексу для групп узлов и диапазонов окон; несовпадение ETag; вытеснение при превышении лимита.
- В браузере: после прогона retry-storm ряд повторения 0 каждого варианта загружается через worker, число окон совпадает с индексом.

## T4.3 Timeline

**Входит.** #14: графики рядов по узлам и метрикам в привычном виде мониторинга; выбор повторения; общий курсор времени.

**Не входит.** Проигрыватель (T4.6), наложение наблюдаемых рядов (этап 3).

**Контракт.**
- Вкладка Timeline показывает группы графиков: интенсивности, задержки, ошибки и отказы, загрузка, очередь. Узлы и метрики выбираются во вкладке; выделение блока на холсте выбирает его ряды.
- Ось — симуляционное время от нуля. Разогрев визуально отделён от измеряемого интервала, интервалы `faults` отмечены с указанием цели.
- Ряды второго варианта можно наложить на те же графики; варианты различаются начертанием и подписаны. Повторение выбирается здесь — номер с нуля, по умолчанию 0 — и входит в контекст результатов.
- При наведении все графики показывают значения окна под указателем. Щелчок фиксирует курсор времени — номер окна в контексте результатов; его используют схема и проигрыватель (T4.6).
- Если окон больше, чем пикселей ширины графика, ряды прореживаются с сохранением минимумов, максимумов и переходов. Окно без значения — разрыв линии, а не ноль.

**Приёмка.**
- Unit: прореживание сохраняет экстремумы; разметка разогрева и отказов.
- E2E: на retry-storm у `baseline` во время отказа растут очередь и ошибки; наложение `no-retries`; щелчок по графику ставит курсор.

## T4.4 Результаты и значок вывода на схеме

**Входит.** #15: итоги прогона на элементах схемы и значок первого насытившегося узла из вывода v1 (#16).

**Не входит.** Текст вывода в Summary (T4.5), кадр окна и анимация (T4.6).

**Контракт.**
- На странице варианта после законченного прогона цвет блока сервиса показывает загрузку, у блока видны средняя очередь и доля отказов очереди. Подпись связи — amplification вызываемого сервиса. Цвет дублируется числом, у шкалы есть легенда.
- Без курсора времени значения — итог измеряемого интервала выбранной точки из сводки, по пулу повторений: те же числа, что в Summary. Схема подписывает режим.
- Значок получает узел, который чаще всего насыщался первым в выбранной точке (`saturation.firstNodes` сводки); подсказка — «N of M replications». Порядок при равенстве задаёт ядро. Без насыщения значка нет. Web не пересчитывает правило по рядам.
- Наложение отключается переключателем, не меняет документы и раскладку и не мешает правке.

**Приёмка.**
- Unit: сопоставление метрик сводки элементам схемы; amplification на связи берётся у вызываемого сервиса; значок для насыщения, для разных первых узлов по повторениям и его отсутствие без насыщения.
- E2E: после прогона retry-storm на странице `baseline` цвет и числа блоков совпадают со сводкой; значок на схеме и текст вывода в Summary указывают один узел; на странице модели наложения нет; правка параметра помечает результаты устаревшими.

## T4.6 Воспроизведение

**Входит.** #25: проигрыватель прогона на схеме, общий курсор с Timeline.

**Не входит.** Частицы-запросы (#26, этап 2).

**Контракт.**
- Проигрыватель: запуск, пауза, несколько скоростей, перемотка ползунком и по одному окну. Положение — курсор времени контекста результатов: движение проигрывателя видно на Timeline, щелчок на Timeline двигает проигрыватель.
- С курсором схема показывает кадр окна из рядов выбранного повторения (T4.2): те же величины, что в T4.4, но по окну, и подпись времени окна и повторения. Сброс курсора возвращает итог из сводки.
- Кадр — функция номера окна (инвариант 4): пауза, перемотка назад и повтор дают тот же кадр. Окна, пропущенные на высокой скорости, на кадр не влияют. Если окна ещё не загружены, проигрыватель ждёт, а не показывает пустой кадр.

**Приёмка.**
- Unit: кадр по номеру окна детерминирован; перемотка к окну даёт тот же кадр, что проигрывание до него.
- E2E: воспроизведение `baseline` на retry-storm — во время отказа на схеме растут очередь и amplification; пауза, перемотка в начало и в середину; курсор Timeline следует за проигрывателем.

## T4.7 Оценка и досчёт

**Входит.** #6: кнопка Estimate и досчёт незаконченного прогона из UI поверх API T2.3 (#89).

**Контракт.**
- Estimate в верхней панели вызывает `POST /estimate` с черновиками изменённых документов, как проверка. Ответ: число задач, ожидаемое время при текущем числе потоков, размер и предупреждения бюджетов. Прогон Estimate не запускает.
- Run перед запуском получает оценку (ADR 0008, п. 8). При предупреждениях бюджета Run просит подтверждения с их текстом, без предупреждений запускает сразу.
- После `CANCELLED` или `FAILED` с незаконченным прогоном доступна кнопка Resume: `POST /runs/{id}/resume`. Новое задание отслеживается и отменяется как обычный запуск. Ответы 409 `RUN_COMPLETE` и 400 с диагностикой изменённых документов показываются с предложением запустить заново.

**Приёмка.**
- Unit: подтверждение при предупреждениях бюджета; разбор ответов досчёта.
- E2E: Estimate на retry-storm совпадает с ответом API на тех же документах; отменённый прогон досчитывается из UI и даёт Summary; правка модели после отмены — понятный отказ досчёта.

## T4.8 Сетка и Map

**Входит.** #104: правка осей `grid` в UI (по плану T3 отнесена сюда) и вкладка Map (дизайн §6.3); сквозной E2E критерия готовности 1.

**Контракт.**
- В `Experiment settings (shared)` можно задать до двух осей. Путь выбирается из параметров блоков и связей модели, значения — списком величин с единицами каталога. Правки — команды с undo/redo. Диагностика по `/grid/…` видна у полей.
- Вкладка Map видна только при непустом `grid` сводки. Одна ось — линия выбранной метрики по значениям оси с 95 % CI, две оси — тепловая карта. Порядок осей и значений, включая повторы, — как в `grid`.
- Метрика — success rate, p95, p99, amplification или загрузка сервиса. Вариант — со страницы. У шкалы цветов есть легенда, значение ячейки видно числом. Данные берутся только из сводки.
- Щелчок по точке или ячейке выбирает точку контекста результатов: Summary, Timeline, схема и вывод переключаются на неё.

**Приёмка.**
- Unit: команды осей сетки и их undo; раскладка ячеек при одной оси и при повторах значений.
- E2E: задать в UI сетку timeout × попытки на копии рабочей области, запустить — тепловая карта; щелчок по ячейке переключает Timeline и схему.
- Сквозной E2E критерия готовности 1: открыть пример → изменить параметр варианта → запустить → Timeline, воспроизведение на схеме и вывод с причиной; Map — на копии с сеткой.
