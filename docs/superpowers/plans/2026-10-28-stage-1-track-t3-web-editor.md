# Дорожка T3 этапа 1: web-редактор — план-контракт

**Цель.** Превратить просмотрщик среза в редактор: правки как команды с undo/redo, правка структуры на холсте с сохранением раскладки, переопределения на страницах вариантов, правка параметров эксперимента, проверка несохранённых правок с вкладкой Problems и правка параметров прямо на схеме.

**Как читать.** Это план-контракт, а не пошаговый рецепт. Для каждой задачи он фиксирует границы, контракты, инварианты и приёмку. Структуру компонентов, состояние и тесты исполнитель выбирает сам, по правилам `AGENTS.md`. Расхождение с ADR или дизайном этапа 1 обсуждается в issue до реализации.

**Источники.** [Дизайн этапа 1](../specs/2026-10-27-stage-1-design.md): §6.1–6.2, §8. [Продуктовое видение](../../product/2026-10-27-product-vision.md), §5.5. ADR [0002](../../architecture/adr/0002-model-pipeline.md) (варианты — переопределения по путям), [0004](../../architecture/adr/0004-canvas-library.md) (React Flow, раскладка отдельно от модели, история на уровне модели), [0005](../../architecture/adr/0005-model-file-format.md) (документы), [0010](../../architecture/adr/0010-api-contract.md) (API, `If-Match`).

## Общие инварианты

1. **Источник правды — документы.** Состояние редактора — загруженные документы модели, раскладки и эксперимента и их сохранённые версии; всё остальное выводится из них. Состояние строится на командах поверх reducer, без новой библиотеки состояния (дизайн §6.2).
2. **Одна правка — одна команда.** Каждое изменение документа пользователем — команда; одно действие пользователя — одна запись истории, даже если меняет несколько документов. Undo и redo восстанавливают документы точно. Выделение, текущая страница, панели и воспроизведение в историю не попадают.
3. **Малошумные диффы.** Команда меняет только то, что затронула: не добавляет значения по умолчанию в нетронутые параметры, не переупорядочивает элементы, не трогает другие документы. Канонический текст пишет сервер.
4. **Каталог — единственный источник** типов палитры, форм, единиц и правил соединения (ADR 0001); типы блоков в коде web не перечисляются, кроме отрисовки.
5. **Правка без потерь.** Сохраняются защиты среза: неверный черновик не даёт сменить элемент, страницу или эксперимент; после конфликта 409 сохранение заблокировано до перечитывания; несохранённые правки не теряются при открытии другого эксперимента без подтверждения.
6. **Тесты.** Unit-тесты команд, undo, переопределений и единиц; E2E по сценариям приёмки на копии рабочей области (дизайн §8). `npm run api:check` проходит.

## T3.1 Команды правок, undo/redo, сохранение документов

**Входит.** Модель состояния редактора на командах; история с undo/redo; сохранение всех изменённых документов; перевод существующей правки параметров модели на команды.

**Не входит.** Новые виды правок (T3.2–T3.5): задача даёт механизм и переводит на него то, что уже есть.

**Контракт.**
- Состояние: для каждого из трёх документов — путь, текущее содержимое, сохранённое содержимое и версия; документ раскладки может ещё не существовать в рабочей области. Признак «есть несохранённые правки» — по каждому документу и общий.
- Команда — чистая функция над документами. История ограничена (не меньше 100 записей), очищается при открытии и перечитывании эксперимента и сохраняется после сохранения: undo после сохранения снова делает документ изменённым.
- Горячие клавиши: Ctrl/Cmd+Z — undo, Ctrl/Cmd+Shift+Z и Ctrl+Y — redo; внутри поля ввода работает штатная отмена поля. Кнопки undo и redo — в верхней панели.
- Сохранение — одна кнопка для всех изменённых документов, каждый со своим `If-Match`; новый документ создаётся без `If-Match`. Порядок: раскладка, модель, эксперимент, чтобы эксперимент не ссылался на ещё не созданную раскладку. Конфликт 409 на любом документе останавливает сохранение, остальные уже сохранённые остаются сохранёнными, редактор показывает, какой документ разошёлся, и предлагает перечитать.
- Если у эксперимента нет `layoutRef`, первая команда, меняющая раскладку, в той же записи истории создаёт документ `<имя эксперимента>.layout.json` рядом с экспериментом и записывает `layoutRef`.

**Приёмка.**
- Unit: каждая существующая команда, её undo и redo дают исходные документы структурно равными; граница истории; очистка при открытии.
- Unit: порядок сохранения и поведение при 409 на втором документе.
- E2E: изменить параметр → undo возвращает значение → redo → сохранить → перечитать страницу: сохранённое значение на месте.

## T3.2 Структура схемы на холсте и раскладка

Объединяет #7 и #10.

**Входит.** Правка структуры модели на странице модели: блоки из палитры, связи между портами, удаление, переименование, копирование; мультивыделение, перемещение, миникарта, масштаб, привязка к сетке; сохранение позиций в документ раскладки.

**Не входит.** Правка структуры на страницах вариантов: варианты со структурными отличиями — отдельные модели (ADR 0002, п. 5). Создание новых документов модели и эксперимента. Иерархия (этап 2).

**Контракт.**
- Перетаскивание типа блока из палитры создаёт блок с идентификатором `<тип>-<n>` с наименьшим свободным `n`; параметры не заполняются, кроме явно введённых. Обязательные параметры без значения подсвечивает проверка (T3.4).
- Связь протягивается от выходного порта к входному. Тип связи — тот, чьё правило `connects` в каталоге совпадает с типами блоков; если подходящего нет, связь не создаётся и UI объясняет причину. Идентификатор — `<from>-to-<to>` с суффиксом при совпадении.
- Удаление выделенного (Delete, Backspace) каскадно в одной команде: связи удалённых блоков, их позиции в раскладке, переопределения вариантов с путями удалённых элементов, отказы `faults` с удалёнными целями и оси `grid`, если сетка уже есть.
- Переименование блока или связи в инспекторе проверяет формат идентификатора по правилам компилятора и уникальность и каскадно в одной команде обновляет `from`/`to` связей, ключи раскладки, пути переопределений, цели отказов и пути осей сетки.
- Копирование и вставка (Ctrl/Cmd+C, Ctrl/Cmd+V) переносят выделенные блоки, связи между ними, параметры, описания и заметки; идентификаторы новые, позиции со сдвигом.
- Перемещение узлов меняет только раскладку. Позиция пишется по пути блока; блок без позиции раскладывается автоматически, как в срезе.

**Приёмка.**
- Unit: каскад удаления и переименования; правило выбора типа связи; генерация идентификаторов.
- E2E: добавить сервис в конец цепочки, соединить, сохранить, перечитать — структура и позиции на месте; удалить блок — исчезают его связи и переопределения; undo восстанавливает всё.
- Перемещение одного блока меняет в документе раскладки только его позицию.

## T3.3 Варианты и параметры эксперимента

Объединяет #9 и #8.

**Входит.** Правка на страницах вариантов как переопределения; управление вариантами; правка параметров прогона и отказов эксперимента.

**Не входит.** Ось `grid` в UI и карта (T4); оценка стоимости (#6).

**Контракт.**
- На странице варианта правка параметра записывает переопределение по самому точному пути: `id.param` для скалярного параметра, `id.param.field` для поля объекта (дизайн §3.3). Если новое значение совпадает со значением модели, переопределение удаляется, а не записывается.
- «Вернуть как в модели» у переопределённого поля и у переопределённого объекта целиком удаляет соответствующие переопределения одной командой. Переопределённые параметры отмечены в инспекторе и значком на элементе схемы.
- Варианты: добавить (новый уникальный идентификатор, подпись, без переопределений или копией текущего варианта), изменить подпись, изменить идентификатор, удалить с подтверждением. Идентификаторы проверяются по правилам компилятора.
- Параметры прогона (повторения, разогрев, измеряемый интервал, seed, лимит реального времени, а после T1.4 — окно рядов) и отказы (добавить, удалить, изменить цель, интервал, множитель обработки, долю отказов) общие для эксперимента и правятся на любой странице; инспектор подписывает их как общие. Единицы длительности и долей берутся из каталога, а не перечисляются в коде.

**Приёмка.**
- Unit: запись переопределения по пути поля, удаление при совпадении с моделью, «вернуть как в модели», каскад при смене идентификатора варианта.
- E2E: на странице `No retries` изменить timeout связи — после сохранения документ эксперимента содержит переопределение, модель не изменилась; «вернуть как в модели» убирает его.
- E2E: добавить вариант, запустить — в Summary три варианта.

## T3.4 Проверка правок и вкладка Problems

**Входит.** Проверка несохранённых правок через API с задержкой; значки на схеме; ошибки у полей; вкладка Problems. Сюда же входит расширение API для проверки черновиков в ядре и сервере.

**Не входит.** Новые правила проверки: линтер — T1.2, его предупреждения появятся здесь автоматически.

**Контракт.**
- API, аддитивно к ADR 0010: тело `POST /api/v1/validate` получает необязательное поле `drafts` — список `{ path, content }` с содержимым документов в форме `DocumentContent`. Сервер проверяет эксперимент так, будто эти документы лежат по указанным путям, в том числе ещё не созданные; хранилище не меняется. Ответ — прежний `ValidationView`. В ядре — перегрузка `Lab.validate` с черновиками. `apps/server/openapi.json` и TS-типы пересоздаются.
- Web отправляет проверку через 500 мс после последней команды с черновиками всех изменённых документов. Ответ на устаревшее состояние отбрасывается.
- Отображение диагностики:
  - значок на блоке или связи по полю `path` — число и наибольшая серьёзность;
  - сообщение у поля инспектора по указателю (`/blocks/<id>/params/<name>[/<field>]`, `/connections/<i>/params/…`, `/variants/<i>/overrides/<path>`, `/execution/…`, `/faults/<i>/…`);
  - вкладка Problems в панели результатов: серьёзность, код, сообщение, место; щелчок выбирает элемент и нужную страницу;
  - диагностика без элемента — только в Problems.
- Ошибки и предупреждения различаются цветом. Run недоступен, пока последняя проверка показывает ошибки; подсказка объясняет почему.

**Приёмка.**
- Сервер: проверка с черновиком видит черновик и не меняет файл; проверка без `drafts` работает как раньше; ответы сверяются с OpenAPI.
- Unit: отбрасывание устаревших ответов; сопоставление указателей с полями и элементами.
- E2E: поставить у сервиса 0 обработчиков без сохранения — значок на блоке, запись в Problems и сообщение у поля; исправить — всё исчезает.

## T3.5 Правка параметров на схеме

**Входит.** #11: правка подписей связи (timeout, число попыток) и ключевых параметров узла (обработчики, очередь, среднее время обработки) прямо на схеме.

**Контракт.**
- Двойной щелчок по значению открывает поле; Enter применяет, Escape отменяет; неверное значение остаётся в поле с сообщением и не применяется.
- Разбор и проверка — те же, что в инспекторе (единицы и диапазоны из каталога). Правка — та же команда, что в инспекторе; на странице варианта она пишет переопределение (T3.3).

**Приёмка.**
- E2E: изменить timeout по подписи связи, undo возвращает значение; на странице варианта такая правка создаёт переопределение.
