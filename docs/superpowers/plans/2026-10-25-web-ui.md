# Resilience Lab Web UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Создать браузерный редактор цепочки сервисов с параметрами эксперимента, baseline/candidate сравнением, sweep-сериями, графиками и импортом/экспортом сценариев.

**Architecture:** `web` — React/TypeScript SPA без собственного backend-состояния: локальный `useReducer` хранит редактируемые варианты, Spring API выполняет валидацию и симуляции, браузер только опрашивает состояние задания. `@xyflow/react` отвечает за блоки/связи, Recharts — за сравнение и sweep-графики; граф и графики с нуля не рисуются.

**Tech Stack:** Node.js 25.5.0, npm 11.8.0, React 19.3.1, TypeScript 7.0.2, Vite 8.3.5, `@vitejs/plugin-react` 6.1.2, `@xyflow/react` 12.12.0, Recharts 3.10.1, Vitest 5.0.5, Testing Library 16.3.3, jsdom 30.1.3, Playwright 1.64.1.

**Spec:** `docs/superpowers/specs/2026-10-25-resilience-lab-design.md`

**Depends on:** `docs/superpowers/plans/2026-10-25-spring-backend-api.md` и уже реализованные core API/модели; server доступен на `127.0.0.1:8080`.

## Global Constraints

- MVP — редактор линейной цепочки, а не универсальный graph IDE; никаких ветвлений, циклов, брокеров, баз данных или совместного редактирования. После MVP обязателен переход к универсальному Graph UI для реальных архитектурных схем, поэтому версионируемая модель документа и компоненты редактора не должны жёстко предполагать, что цепочка — единственно возможная топология навсегда.
- Все длительности — миллисекунды; интенсивность — запросы/мс; числовые поля не принимают `NaN`, `Infinity`, пустую строку или значения вне границ core.
- Браузер общается только с локальным Spring API через Vite proxy `/api`; production data, токены и внешние observability endpoints не используются.
- `@xyflow/react` используется для графа, Recharts для графиков, `useReducer` для состояния; дополнительный state manager или UI-kit не добавлять.
- Пользователь может выбрать baseline/candidate или одномерный sweep, но не оба одновременно; `ExperimentSubmission` содержит ровно одно из полей `experiment`/`sweep`.
- Результат более старого запроса/пolling не имеет права перезаписать состояние нового задания.
- Стандартные проверки: `npm run lint`, `npm run test`, `npm run build`, `npm run test:e2e` плюс полный JVM build.
- Визуальный сценарий и результат можно экспортировать; скачанный сценарий после повторного импорта сохраняет конфигурацию и seed.

## Review Focus

- Разорванная цепочка или связь, создающая ветвление: UI показывает ошибку и не отправляет эксперимент (Task 3, `rejects invalid topology before submission`).
- Пустое/отрицательное/нечисловое значение: не превращается молча в `0` или `NaN` (Task 4, `rejects invalid numeric input`).
- Смена задания во время polling: результат старого запроса игнорируется (Task 5, `ignores stale job responses`).
- Импорт с неизвестными полями или нарушенной схемой: отображается ошибка backend, editor state не портится (Task 4, `rejects invalid import without replacing state`).
- Полный пользовательский сценарий: цепочка → деградация → эксперимент → графики → экспорт (Task 7, `completes the real browser workflow`).
