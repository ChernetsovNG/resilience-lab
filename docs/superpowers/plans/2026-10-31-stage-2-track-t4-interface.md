# Дорожка T4 этапа 2, срез 1: интерфейс к графу, репликам, пулам и отказам — план-контракт

**Цель.** Сделать всё, что умеет ядро первого среза этапа 2, доступным мышью: собрать сквозной кейс без правки файлов и увидеть в результатах группы реплик, худшую реплику и насыщенные пулы.

**Как читать.** Это план-контракт, а не пошаговый рецепт. Для каждой задачи он фиксирует границы, контракты для соседних задач, инварианты и приёмку. Структуру компонентов, реализацию и тесты исполнитель выбирает сам, по правилам `AGENTS.md` и `web/AGENTS.md`. Расхождение с ADR, дизайном или концепцией интерфейса обсуждается в issue до реализации.

**Источники.** [Дизайн первого среза этапа 2](../specs/2026-10-30-stage-2-slice-1-design.md): §3.2–§3.6, §6, §7.2. Формат результатов — [docs/results-format.md](../../results-format.md).

## Исходное состояние

Ядро после T1–T3 умеет граф, группы реплик с `replicaOverrides`, сценарий сервиса, маршрутизатор, БД, пул на связи, пулер, профили нагрузки, пять видов отказов, строки групп, насыщение всех наборов слотов и запас по ёмкости. Web по инварианту 6 сохраняет всё это без потерь, но показывает и правит частично:

- **Схема.** У `database`, `pooler` и `router` под именем стоит идентификатор типа, а не подпись и ключевые параметры. В палитре у БД и пулера вместо значка первая буква названия. Подпись связи показывает только timeout и число попыток: ни размера пула, ни политики балансировки.
- **Группа реплик** выглядит как обычный сервис. Число реплик правится общим полем инспектора, отличия реплик (`replicaOverrides`) только сохраняются.
- **Сценарий сервиса** не показывается и не правится.
- **Профиль нагрузки** — массив `load.points` в инспекторе только для чтения (JSON).
- **Отказы.** Вид отказа только показан, сменить его нельзя. В списке целей нет реплик и копий связей. Отказ создаётся только в настройках прогона.
- **Результаты.** Строки групп в Ответе, Map и на схеме не показываются (T3.2 их исключил до T4). Таблицы реплик и полосы min–max нет. CLI не показывает группы.

Готовы и используются: ход эксперимента под схемой (#243), страница варианта (#188), справка и подсказки «?» (#189).

## Общие инварианты

1. **Форматы не меняются.** T4 не меняет формат документов и артефакта. Если задаче не хватает поля в ядре или API, это обсуждается в issue до реализации.
2. **Одна правка — одна запись Undo.** Любое действие редактора — одна команда редактора: Undo возвращает документ целиком, включая связанные поля (например, смена вида отказа заменяет набор полей одной записью).
3. **Страница варианта.** Структура — блоки, связи, сценарий, отличия реплик — на странице варианта только для просмотра, с подсказкой «структура правится на странице модели» (#188). Параметры блоков и связей правятся как переопределения варианта. Параметры прогона и отказы общие для эксперимента и правятся на любой странице (дизайн этапа 1, §6).
4. **Начальные значения.** Новый элемент — шаг сценария, точка нагрузки, отказ, отличие реплики — получает допустимые значения из `ParamDescriptor.initial` каталога (#242), а не пустые поля с ошибками.
5. **Подсказки.** Пояснения к полям — за значком «?» общим компонентом `HelpHint` (#189), по правилу §4.3 концепции «Подсказки полей». Строк описаний под полями нет.
6. **Тексты** — через каталог сообщений, `en` и `ru`; тест полноты переводов проходит.
7. **Плотность.** Новые элементы схемы не уменьшают область холста; узел группы не выше обычного узла сервиса больше чем на высоту «стопки». Проверка — замер в PR, как в #243.
8. **Проверки** по `web/AGENTS.md`: затронутые E2E локально, полный набор — в CI. В PR — скриншоты из `pr-assets` на русском интерфейсе.

## T4.1 Новые блоки и связи на схеме

**Входит.** Вид узлов `database`, `pooler`, `router` и подписи связей с пулом и балансировкой; значки палитры.

**Не входит.** Группы реплик (T4.2); результаты (T4.3).

**Контракт.**
- Под именем узла — ключевые параметры, по паре «название: значение» в строке, как у сервиса (#227), со встроенной правкой:
  - `database` — соединения, очередь, среднее время запроса;
  - `pooler` — клиентские подключения, серверный пул, предел ожидания;
  - `router` — политика маршрутизации.
- Ни у одного узла под именем не стоит идентификатор типа. Тип виден по значку и подсказке.
- Подпись связи `call` с пулом показывает его размер (например, «пул 10»), связи в группу реплик — политику балансировки, если она задана. Подпись остаётся одной компактной плашкой.
- Значки палитры для `database` и `pooler` — в стиле существующих: простая линия, `currentColor`.

**Приёмка.**
- Unit: строка параметров каждого типа; подпись связи с пулом и с балансировкой; значки БД и пулера вместо букв.
- E2E: модель «сервис с пулом → пулер → БД» — на схеме видны параметры всех трёх и «пул N» на связи; встроенная правка соединений БД пишет документ одной записью Undo.

## T4.2 Группа реплик: вид и правка

**Входит.** Вид группы на схеме; число реплик и отличия реплик в инспекторе.

**Не входит.** Результаты группы (T4.3); сворачивание и разворачивание групп на холсте (точка расширения, дизайн §9).

**Контракт.**
- Сервис с `replicas > 1` на схеме — узел «стопкой» с пометкой «×N». При `replicas = 1` — обычный узел.
- В инспекторе сервиса — число реплик и таблица отличий реплик: строка на реплику с отличиями, столбцы — переопределённые параметры. Добавить отличие для реплики `k`, изменить, удалить — одной записью Undo каждое. Отличие для номера больше числа реплик подсвечивается, как ядро (`REPLICA_*`).
- На странице варианта число реплик правится как переопределение варианта; таблица отличий только для просмотра.

**Приёмка.**
- Unit: «стопка» и «×N» только при `replicas > 1`; добавление, изменение и удаление отличия — по одной записи Undo, документ совпадает с ожидаемым `replicaOverrides`.
- E2E: сделать сервис группой из трёх, задать реплике #2 другое время обработки, сохранить, перечитать, запустить — прогон завершается, документ без потерь.

## T4.3 Результаты групп на схеме, в инспекторе и Ответе

**Входит.** Показ строк групп из T3.2 и худшей реплики; выбор реплики; группы в Ответе и Map.

**Не входит.** Timeline (T4.4).

**Контракт.**
- **Схема.** Узел группы показывает сводное значение и худшую реплику, например «загрузка 34 % · худшая #2: 97 %». Цвет узла — по худшей реплике. Подписи связей группы — по сводной строке связи.
- **Инспектор группы.** Таблица реплик: номер, загрузка, средняя очередь, отказы, p99 — с сортировкой по столбцу. Щелчок по строке выбирает реплику: инспектор показывает её результаты и её отличия, на схеме выбрана группа с отметкой номера.
- **Ответ и Map.** Строки групп появляются рядом с сервисами; реплики раскрываются внутри группы. Вывод о насыщении уже называет экземпляр (`order-service#2`) — он ведёт к реплике в инспекторе.
- Данные — из сводки и рядов T3.2; значения не пересчитываются в web заново, кроме выбора отображения.

**Приёмка.**
- Unit: подпись узла группы со сводным значением и худшей репликой; цвет по худшей; сортировка таблицы; выбор реплики.
- E2E: модель с группой из трёх и замедленной репликой #2 — на схеме «худшая #2», в инспекторе #2 первая при сортировке по загрузке, в Ответе группа раскрывается до реплик.

## T4.4 Группы на Timeline

**Входит.** Линия группы и полоса min–max по репликам; подгрузка рядов реплик по выбору.

**Не входит.** Новые виды графиков.

**Контракт.**
- Для выбранной группы Timeline показывает сводную линию и полосу от наименьшего до наибольшего значения среди реплик (поля min/max строки группы).
- Ряды отдельных реплик загружаются только по выбору: «добавить реплику #k на график». До этого части рядов экземпляров не запрашиваются (части `GROUP` и `INSTANCE`, T3.2).
- Воспроизведение и общий курсор работают с группой так же, как с сервисом.

**Приёмка.**
- Unit: полоса строится из min/max; добавление реплики добавляет её линию.
- E2E с перехватом запросов: при выборе группы не запрашиваются части рядов экземпляров; после добавления реплики запрашиваются только её ряды.

## T4.5 Редактор сценария сервиса

**Входит.** Список шагов сценария в инспекторе сервиса.

**Не входит.** Вид сценария в стиле sequence-диаграммы (дизайн, §10, вопрос 1); шаг `parallel` (точка расширения).

**Контракт.**
- Раздел «Сценарий» в инспекторе сервиса: упорядоченный список шагов «обработка» и «вызов». У вызова — выбор исходящей связи этого сервиса. У обработки — необязательные собственные время и доля ошибок, иначе действуют параметры сервиса.
- Добавить шаг, удалить, переставить (кнопками и клавиатурой; перетаскивание — по желанию исполнителя) — одной записью Undo каждое.
- Без явного сценария раздел показывает действующий по умолчанию порядок (обработка, затем вызовы в порядке связей) с действием «задать свой сценарий», которое записывает этот порядок явно.
- Удаление последнего шага убирает поле `scenario`. Ошибки ядра (`SCENARIO_*`) показываются у шага.
- На странице варианта сценарий только для просмотра.

**Приёмка.**
- Unit: добавление, удаление и перестановка шагов; явный сценарий из действующего по умолчанию; выбор связи только из исходящих; ошибки у шага.
- E2E: сервис с двумя исходящими связями — задать сценарий «обработка → вызов A → вызов B → вызов A», сохранить, перечитать, запустить.

## T4.6 Редактор профиля нагрузки

**Входит.** Таблица точек нагрузки клиента и график интенсивности в инспекторе.

**Не входит.** Перебор профиля сеткой (запрещён ядром); синусоида, всплески по расписанию, профиль из данных (точки расширения).

**Контракт.**
- Раздел «Нагрузка» в инспекторе клиента: таблица точек (время, интенсивность) с единицами; добавить, удалить, изменить точку — одной записью Undo. Новая точка получает время после последней и её интенсивность.
- Рядом — маленький график кусочно-линейной интенсивности с зонами разогрева и измерения; он совпадает с кривой нагрузки в полосе хода эксперимента (#243), которая обновляется сразу.
- Ошибки точек ядра (порядок времени, отрицательные значения) — у соответствующей строки.
- На странице варианта профиль правится как переопределение варианта целиком.

**Приёмка.**
- Unit: добавление, удаление и правка точки; переопределение профиля на варианте; ошибка порядка времени у строки.
- E2E: задать рампу 10 → 100 RPS за 30 s, сохранить, перечитать, запустить; полоса хода эксперимента показывает рампу.

## T4.7 Редактор отказов

**Входит.** Полный редактор отказов в настройках прогона и создание отказа из инспектора элемента.

**Не входит.** Перетаскивание интервалов отказов мышью на полосе хода эксперимента (следующий шаг после этого среза); постепенная деградация, периодические сбои, отказ зоны.

**Контракт.**
- **Вид — выпадающим списком.** Смена вида заменяет поля прежнего вида полями нового с начальными значениями одной записью Undo.
- **Виды, недопустимые для цели, недоступны:** потеря ёмкости — только у цели с набором слотов; на связи без пула и на `route` её нет.
- **Цели:** блоки, реплики `<сервис>#k` групп, связи `call` и `route`, копии связей реплик.
- **Подсказки «?» у полей** объясняют действие с формулой. Подпись поля зависит от цели: «время обработки» у блока, «сетевая задержка» у связи.
- **«Добавить отказ» в инспекторе блока, реплики или связи** создаёт отказ с этой целью и открывает его в настройках прогона.
- **Список параметров оси перебора** не предлагает параметры, которые ядро для этой цели отвергает. Например, `pool` исходящей связи пулера (`POOLER_CALL_POOL`).

**Приёмка.**
- Unit: смена вида меняет набор полей одной записью Undo; недопустимые сочетания вида и цели недоступны; реплики и копии связей в списке целей; «Добавить отказ» из инспектора подставляет цель.
- E2E: на модели с группой из трёх добавить из инспектора реплики #2 «чёрную дыру» на 20–30 s, сменить вид на замедление ×4, сохранить, перечитать, запустить; полоса хода эксперимента показывает отказ реплики #2.

## T4.8 CLI: группы в сводке

**Входит.** Вывод групп в `run` и `summary`.

**Не входит.** Изменение формата вывода для моделей без групп.

**Контракт.**
- После строк сервисов CLI печатает строки групп со сводными значениями и худшей репликой; флаг (название выбирает задача) раскрывает реплики внутри группы.
- Для моделей без групп вывод не меняется.

**Приёмка.**
- Тест CLI: модель с группой — строки группы и худшая реплика; с флагом — строки реплик; `retry-storm` — вывод прежний.
