# Формат артефакта прогона

Манифест и сводка используют `schemaVersion: 2`. Внутренние файлы задачи используют версию 1. Версия входных документов остаётся прежней. Старые артефакты не мигрируются: их нужно получить новым запуском. Каталог прогонов пропускает неподдерживаемые версии; явное чтение через API возвращает HTTP 400 с кодом `RUN_VERSION_UNSUPPORTED`.

Основания: [дизайн этапа 1](superpowers/specs/2026-10-27-stage-1-design.md), [ADR 0008](architecture/adr/0008-run-results.md), [ADR 0009](architecture/adr/0009-execution.md), [профиль S5](research/2026-10-28-latency-sketch.md).

## Файлы

Пример структуры каталога:

```text
.results/<эксперимент>/<прогон>/
  manifest.json
  summary.json
  series/<вариант>/p0/rep-0/
    replication.json
    index.json
    part-0.json.gz
    part-1.json.gz
```

Нумерация повторений, окон и частей начинается с нуля. До добавления сетки параметров единственная точка называется `p0` и не имеет координат.

`manifest.json` перечисляет относительные пути всех файлов артефакта и SHA-256 их сохранённых байтов. Для gzip это хеш сжатых байтов. Сам манифест в список не входит; он записывается последним. В нём также находятся версии приложения и KSL, версия назначения потоков, seed, варианты, число повторений и метаданные рядов `series`: интервалы в миллисекундах, шаг окна, профиль скетча, версия библиотеки, единица времени, способы учёта событий и точек сетки.

Поле `documents` содержит SHA-256 канонической записи модели и эксперимента: ключи объектов упорядочены кодеком документов. Поэтому перестановка блоков и форматирование JSON не меняют артефакт. Проверка принятых в очередь документов по `expectedVersions` и HTTP `If-Match` по-прежнему использует хеш исходных байтов документа.

`complete: true` означает, что все задачи и сводка записаны. При ошибке или отмене сохраняются готовые файлы задач, сводка не создаётся, манифест получает `complete: false`. У незаконченной задачи могут остаться части без индекса или итогов повторения. Такие файлы перечислены в неполном манифесте. Исключение отмены остаётся `CancellationException`. Вызов с уже установленным признаком отмены не создаёт артефакт.

Запись начатой части завершается в отдельном потоке, который отмена не прерывает. Исполнитель ждёт завершения активных задач перед публикацией неполного манифеста. После последней проверки отмены окончательная запись сводки и манифеста завершается целиком; прерывание вызывающего потока восстанавливается после записи.

## Окна и статистики

`execution.window` задаётся длительностью с единицами, например `"100ms"`. По умолчанию шаг равен `measurement / 100`. Окна покрывают `[0, warmup + measurement)` от нуля; последнее может быть короче. Поля `startMs` и `durationMs` каждого окна задают его фактический интервал. Событие на границе попадает в следующее окно; событие в конце интервала и последующий run-out в ряды не входят.

Ряды учитывают события по времени их возникновения, включая прогрев. Для клиента сохраняются `originalArrivals`, `successes`, `failures` и `latency`; завершение и задержка относятся к окну завершения запроса.

Для сервиса сохраняются:

- `offeredAttempts` — попытки, дошедшие до сервиса после сетевой задержки запроса;
- `admittedAttempts` — попытки, принятые в очередь или сразу занявшие обработчик;
- `queueRejections` — отказы при переполнении очереди;
- `successes` и `failures` — успешные и неуспешные завершения принятой работы до сетевой задержки ответа;
- `timeouts` и `retries` — таймауты ожидания downstream-вызова и повторы, отнесённые к вызывающему сервису;
- `busyHandlerTimeMs` и `handlers` — сумма времени занятости и число обработчиков;
- `queueLengthIntegralMs` — интеграл длины очереди по времени;
- `latency` — время пребывания попытки в сервисе: очередь и удержание обработчика. Немедленный отказ очереди добавляет нулевое время пребывания.

Загрузка окна вычисляется как `busyHandlerTimeMs / (handlers * durationMs)`, средняя очередь — как `queueLengthIntegralMs / durationMs`. Число обработчиков клиента равно нулю; эти формулы применяются к сервисам.

Каждое поле `latency` содержит `count`, `sumMs` и `sketch`. Среднее — `sumMs / count`, пустая выборка не имеет среднего. Сумма копится в порядке событий; значения из представителей корзин для среднего не используются.

## Части и индекс

`part-<k>.json.gz` содержит сжатый UTF-8 JSON `SeriesPart`: `schemaVersion`, `profile`, полуоткрытый диапазон индексов `fromWindow`/`untilWindow` и массив `nodes`. У узла есть `id` и массив `windows` в порядке времени. Текущий писатель использует диапазон из одного окна и делит его узлы на группы в лексикографическом порядке. Каждая пара «узел × окно», включая пустые окна, присутствует ровно один раз.

Лимит части до сжатия — 4 МиБ, то есть 4 194 304 байта. Писатель считает фактически закодированные байты вместе с заголовком и разделителями. Если не помещается один узел в одном окне, расчёт завершается ошибкой с узлом, окном и лимитом. Данные не обрезаются. Gzip не содержит времени запуска, поэтому одинаковые данные дают одинаковые байты.

`index.json` содержит `schemaVersion`, `endMs`, `windowMs` и список `parts`. Для каждой части указаны `file`, `nodes`, `fromWindow`, `untilWindow`, `uncompressedBytes` и `sha256`. Индекс записывается после всех окон задачи.

Сборщик передаёт закрытое окно писателю и освобождает его. В памяти остаются текущее окно, текущая часть, статистики повторения и метаданные индекса; все оконные скетчи прогона одновременно не хранятся.

## Скетч задержки

Профиль `ddsketch-bitwise6-rational-v1` использует `sketches-java:0.8.3`: `BitwiseLinearlyInterpolatedMapping(6)` с представителем `lowerBound * 129/128`. Оконные накопители используют `SparseStore`, итоги и слияние — `UnboundedSizeDenseStore`.

Поле `sketch` — массив `[zeroCount, index, count, ...]`. Индексы строго возрастают, ненулевые counts положительны, целые записываются десятичными числами без экспоненты. Пустое распределение — `[0]`. Профиль указан один раз на часть или файл итогов. Ноль хранится точно.

До изменения скетча проверяются конечность и диапазон значения, будущие count и диапазон корзин. Разрешены ноль и положительные значения в `[2^-1021, 2^1023)` ms; общий count не больше `9 007 199 254 740 990`, занятый диапазон — не больше 2048 адресов корзин. Ошибка оставляет принимающий скетч неизменным. Сливаются только одинаковые профиль и единица. Целые counts дают одинаковые корзины при любом допустимом порядке слияния.

Квантили сохраняют соглашение KSL: позиция `p * (n + 1)`, крайние позиции ограничены первым и последним представителем, между соседними порядковыми статистиками применяется `a + fraction * (b - a)`. Пустой скетч возвращает `null`. Относительная погрешность квантилей для проверенного диапазона задержек `0.001–60000 ms`, включая точные нули, не больше 0,78125 % с учётом округления binary64. Для крайне малых результатов интерполяции относительная гарантия не заявляется; ограничение описано в S5.

## Итоги повторения и сводка

`replication.json` содержит `schemaVersion`, `profile`, `unit` и `result`. В `result` находятся счётчики исходных запросов, `allLatency`, `successfulLatency`, `failedLatency` и статистики сервисов. Списков отдельных задержек или времён поступления в файле нет.

Когорта итогов состоит из запросов, пришедших за измеряемый интервал `[warmup, warmup + measurement)`. Их исходы, задержки и вызванные ими попытки учитываются и во время run-out. Занятость и очередь сервисов интегрируются только по измеряемому интервалу, включая работу, которая поступила во время прогрева. В итогах сервисов `failures` сохраняет прежний смысл локальных отказов; оконное поле `failures` считает все неуспешные завершения принятой работы.

`summary.json` собирается только из записанных `replication.json` в порядке «вариант, точка, повторение». Пул задержек строится слиянием скетчей, его среднее — из counts и сумм; в `LatencyDistribution.statistics` сохраняются достаточные статистики. `AggregateServiceMetrics.totals` содержит числители, знаменатели и интегралы сервисов.

Статистики независимых повторений остаются отдельными: `MetricSummary` для success rate, p95/p99 и amplification. Их доверительные границы Стьюдента не обрезаются до физического диапазона. Погрешность скетча и неопределённость между повторениями имеют разный смысл; pooled p99 не вычисляется усреднением p99 повторений.
