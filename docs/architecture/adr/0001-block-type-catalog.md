# ADR 0001. Каталог типов блоков и величины с единицами

Дата: 2026-10-27  
Статус: принято  
Связано: [целевая архитектура](../2026-10-27-target-architecture.md), решение A2; [продуктовое видение](../../product/2026-10-27-product-vision.md), §4, §5.6, §5.7.

## Контекст

Сейчас каждый блок — отдельный класс Kotlin (`ServiceSpec`, `LinkSpec` в `core/src/main/kotlin/resiliencelab/core/scenario/Models.kt`). Типы TypeScript продублированы вручную в `web/src/api/types.ts`, формы написаны вручную под каждый блок, параметры серий — перечисление `SweepParameter` из пяти значений, отдельно в Kotlin и TypeScript. Новый тип блока затрагивает около семи мест в трёх модулях.

Видение добавляет десятки типов блоков, составные блоки с масками и серии по любому параметру; разработку ведут параллельные исполнители. Значения без единиц уже привели к ошибке (#20).

## Решение

1. Ядро содержит каталог типов примитивов. Описание типа в Kotlin задаёт идентификатор и версию; порты и их вид; параметры — тип значения, физическую величину и допустимые единицы, диапазон, значение по умолчанию, описание и признак «можно перебирать в серии»; реализацию для движка.
2. В файлах модели экземпляр хранится обобщённо: тип и значения параметров. Ядро раскладывает их в типизированный класс этого типа; код симуляции работает только с типизированными классами.
3. Каталог — единственный источник для палитры и форм UI, проверки параметров, справки CLI и схемы файлов. Ядро отдаёт его через API и CLI.
4. Составной блок описывается тем же контрактом: порты и параметры маски. Для UI и CLI он выглядит как примитив.
5. Любой параметр адресуется путём: путь блока в иерархии и имя параметра, например `payments/payment-service/db-pool.size`. Серии, варианты и требования ссылаются на пути; перечисления параметров не нужны.
6. Величины в файлах пишутся с единицами: `250ms`, `2s`, `120/s`, `0.5%`. Ядро переводит их во внутренние единицы, UI показывает привычные.
7. Новые примитивы добавляет только ядро (драйвер D4).

## Последствия

- Новый примитив — описание типа, реализация для движка и тесты в ядре; UI и CLI подхватывают его без отдельной работы, кроме блоков с особым видом на схеме.
- Формы UI строятся по каталогу, ручные инспекторы постепенно заменяются; ручное дублирование типов блоков в TypeScript уходит.
- Формат сценария MVP (`schemaVersion` 1) мигрирует в новый формат (решение A11).
- В ядре нужен разбор и печать величин с единицами, в UI — их отображение.

## Рассмотренные варианты

- **Класс на каждый блок с генерацией типов TypeScript.** Строгая типизация, но формы, перечисления серий и проверки остаются ручными во многих местах.
- **Только обобщённые словари параметров, в том числе в ядре.** Контракт проще, но код симуляции теряет типизацию и проверки компилятора.
- **Числа в фиксированных единицах (`timeoutMs`).** Разбор проще, но единица живёт в имени поля и в схеме, а не рядом со значением; ошибки вроде #20 остаются возможны.
