# ADR 0002. Конвейер модели и эксперимент как переопределения

Дата: 2026-10-27  
Статус: принято  
Связано: [целевая архитектура](../2026-10-27-target-architecture.md), решение A3; [ADR 0001](0001-block-type-catalog.md); [продуктовое видение](../../product/2026-10-27-product-vision.md), §5.7.

## Контекст

В MVP данные идут напрямую из классов сценария в модель KSL: `ScenarioCodec` → `ScenarioValidator` → `ReliabilityModel`. Вариант эксперимента хранит полную копию сценария (`ExperimentVariant.scenario`), часть проверок продублирована в TypeScript (`web/src/scenario/chainGuards.ts`).

Дальше появятся иерархия с масками и библиотекой (§5.7 видения), а формат файлов и движок могут поменяться по итогам исследований S2 и S1. Ошибки должны указывать на блок и место в файле, результаты — сворачиваться по уровням иерархии.

## Решение

1. Один конвейер в ядре для CLI и сервера: разбор файлов → разрешение ссылок на библиотечные блоки → применение масок → проверка → разворачивание иерархии → промежуточное представление (IR), плоский граф примитивов → адаптер движка → прогон.
2. IR не зависит ни от формата файлов, ни от движка: смена формата затрагивает только разбор, смена движка — только адаптер.
3. Каждый элемент IR хранит происхождение: документ, место в нём и путь блока в иерархии. Диагностика указывает на блок и строку файла; результаты по элементам IR сворачиваются вверх по иерархии, а вывод показывает путь.
4. Проверка модели целиком выполняется только в ядре. Диагностика имеет код, уровень (ошибка или предупреждение) и место. UI проверяет отдельные поля по каталогу (ADR 0001), а модель целиком — через API. Линтер схемы (#18) работает в том же конвейере.
5. Эксперимент — ссылка на модель и варианты в виде наборов переопределений параметров по путям (ADR 0001, п. 5). Серии перебирают пути, требования (решение A10) ссылаются на пути. Варианты со структурными отличиями описываются отдельными моделями.

## Последствия

- В `core` появляется компилятор модели, отдельный от адаптера KSL; адаптер принимает только IR.
- Путь MVP `ScenarioCodec` → `ReliabilityModel` переносится на IR; копии сценариев в вариантах уходят при миграции формата.
- Проверки в TypeScript вроде `chainGuards.ts` заменяются диагностикой ядра.
- Для больших моделей (драйвер D2) время конвейера нужно измерять; при необходимости — инкрементальная пересборка.

## Рассмотренные варианты

- **Прямо из модели файлов в движок, как в MVP.** Меньше кода, но формат, движок и иерархия связаны напрямую, а диагностику трудно привязать к блокам.
- **Копия модели на каждый вариант.** Просто, но шумные диффы, дублирование и сложное сравнение вариантов.
