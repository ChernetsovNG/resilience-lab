# ADR 0008. Результаты прогона — каталог артефакта

Дата: 2026-10-27  
Статус: принято  
Связано: [целевая архитектура](../2026-10-27-target-architecture.md), решение A7; [исследование объёма результатов](../../research/2026-10-27-results-volume.md) (#48); [ADR 0003](0003-workspace.md), [ADR 0007](0007-simulation-engine-ksl.md).

## Контекст

Продукту нужны сводки, временные ряды по узлам для таймлайна и воспроизведения, выборочная трасса для частиц-запросов, серии и 2D-карты. Размер модели заранее не ограничен (D2): на 5000 листьях и сетке 5×5 с десятью повторениями только десять метрик рядов занимают около 60 ГБ без сжатия. Исследование #48 сравнило JSON+gzip, CSV, Arrow IPC и Parquet. Parquet лучше по размеру и умеет выборочное чтение, но на JVM требует `parquet-hadoop` и `hadoop-common`; на первом этапе модели малы, и формат хранения почти не влияет на время.

## Решение

1. Результат прогона — каталог артефакта в рабочей области (`.results/` в файловой реализации, ADR 0003): `manifest.json`, `summary.json`, части рядов в `series/` и трассы в `traces/`, разбитые по варианту, точке сетки и повторению, при необходимости — по группам узлов и времени; индексы частей лежат рядом с ними.
2. Манифест содержит версию схемы, версии приложения и движка, хеши модели и эксперимента, seed и потоки каждого повторения, координаты сетки, единицы и смысл метрик, интервалы, параметры выборки трассы, фактическую полноту, относительные пути, формат и контрольные суммы частей. Незаконченный артефакт явно помечен и не выглядит готовым.
3. Сводка и манифест — JSON. Подробные части пока пишутся в JSON+gzip, без новых зависимостей; формат каждой части указан в манифесте. Parquet или другой колоночный формат добавляется отдельным решением, когда части или время их чтения превысят бюджеты.
4. Агрегаты хранят достаточные статистики, а не готовые значения: числитель и знаменатель долей, занятое время и ёмкость для загрузки, интегралы и длительности для очередей. Квантили сворачиваются по уровням иерархии сливаемыми скетчами с известной погрешностью; усреднять p99 нельзя.
5. Различаются статистика по пулу наблюдений и статистика по независимым повторениям, как в `MetricsAggregator`; доверительные границы не обрезаются.
6. Ряды собирает собственная реализация адаптера, а не штатный `TimeSeriesResponse` (ADR 0007). Трасса выбирает целые исходные запросы независимо от генераторов симуляции и сохраняет всех потомков, включая orphaned work.
7. UI сначала загружает сводку, затем — выбранные узлы текущего уровня, метрики и диапазон времени; тяжёлое декодирование идёт в Web Worker. Для экрана ряды прореживаются с сохранением минимумов, максимумов и переходов; агрегаты уровней строятся по запросу, а не дублируются заранее.
8. Вместо предела числа блоков действуют бюджеты: стартовые ориентиры — части до 64 МиБ, ответ UI до 4 МиБ, кэш декодированных данных порядка 64 МиБ. До запуска показывается оценка числа событий, строк и места; при превышении бюджета — явная остановка или согласованное снижение детализации с пометкой неполноты, без молчаливого обрезания.
9. `.results/` по умолчанию в `.gitignore`. Чтобы сохранить результат для ADR или ревью, пользователь явной командой копирует его манифест и сводку в отслеживаемое место; подробные части в git не попадают.

## Последствия

- Нужны схема манифеста и сводки, писатель частей в ядре и загрузчик частей в UI.
- Бюджеты — стартовые ориентиры: их нужно проверить на готовом UI.
- Переход на Parquet затронет только писатель и загрузчик частей благодаря полю формата в манифесте.
- Остаётся согласовать семантику окон, состав событий трассы для воспроизведения и выбор скетча квантилей; это входит в дизайн этапа 1 (#5).

## Рассмотренные варианты

- **Parquet+Snappy сразу.** Меньше размер и выборочное чтение по HTTP Range уже на первом этапе, но в сервер и CLI добавляются `parquet-hadoop` и `hadoop-common`.
- **Arrow IPC.** Самые быстрые запись и чтение, но в пять раз больше места и нужны дополнительные флаги JVM.
- **Манифест и сводка всегда в git, или Git LFS для всего.** Автоматическая запись в историю каждого прогона или настройка LFS у каждого пользователя не нужны для типичного сценария.
