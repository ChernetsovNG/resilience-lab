# ADR 0006. Потоки случайных чисел привязаны к путям блоков

Дата: 2026-10-27  
Статус: принято  
Связано: [целевая архитектура](../2026-10-27-target-architecture.md), решение A3 и драйвер D6; [ADR 0002](0002-model-pipeline.md); [исследование формата файлов](../../research/2026-10-27-model-file-format.md), раздел «Порядок и воспроизводимость».

## Контекст

Исследование #47 показало, что `ReliabilityModel` назначает потоки случайных чисел по индексам сервисов и связей. Если переставить элементы массива в файле, результат при том же seed меняется. После разворачивания иерархии (ADR 0002) порядок листовых блоков тем более не должен влиять на расчёт. Сравнение baseline и candidate опирается на согласованные случайные потоки (проектный дизайн, §2, §9).

## Решение

1. Каждый источник случайности — поступления, время обработки, исходы попыток, сетевые задержки, jitter в backoff и последующие — получает поток, однозначно определённый seed эксперимента, номером повторения, устойчивым путём блока в иерархии и ролью источника внутри блока.
2. Порядок блоков в файлах, порядок разворачивания иерархии и параллельное выполнение на назначение потоков не влияют.
3. Добавление или удаление блока не меняет потоки остальных блоков.
4. Блоки с одинаковыми путями в разных вариантах эксперимента получают одинаковые потоки, поэтому сравнение вариантов идёт на согласованных случайных числах.
5. Конкретный механизм — производные seed, подпотоки KSL или их сочетание — выбирается по итогам исследования KSL (#46) с проверкой независимости потоков.

## Последствия

- Существующие сценарии в новой версии дадут другие числа при том же seed; по драйверу D6 это допустимо, изменение отмечается в истории версий.
- Нужны тесты: перестановка массивов, разный порядок разворачивания и параллельный расчёт дают одинаковые результаты; добавление блока не меняет потоки остальных.
- Пути блоков становятся частью контракта воспроизводимости: переименование блока меняет его потоки.

## Рассмотренные варианты

- **Оставить назначение по порядку массивов.** Порядок пришлось бы сделать частью модели и сохранять при любой записи и разворачивании; перестановка или вставка блока незаметно меняла бы результаты остальных.
