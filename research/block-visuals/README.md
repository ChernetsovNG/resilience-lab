# Прототип визуальных блоков (#346)

Изолированный исследовательский прототип. Не входит в сборку приложения, не меняет `web/`, ядро или API. Правила: [AGENTS.md](../../AGENTS.md). Все контуры и SVG-значки здесь нарисованы самостоятельно; сторонняя графика в исходники не скопирована.

## Запуск

Нужен Node.js 26 и npm из его комплекта. Из этого каталога:

```sh
npm ci
npx playwright install chromium
npm run build
npm run bench
```

`bench` сам поднимает отдельный `vite preview` на `127.0.0.1:15246`, запускает headless Chromium и закрывает их после завершения. Если порт занят, задайте `BENCH_PORT=15247`. Результаты перезаписываются в `results/raw.json` и `results/summary.json`. Скриншоты проверки пишутся только в `/tmp/issue-346-*.png`, в репозиторий не включаются. Изменять `dist/` во время замера нельзя.

Для ручного просмотра:

```sh
npm run preview
```

- [Галерея контуров и значков](http://127.0.0.1:15246/?gallery=1&mode=parametric): шесть типов в размерах 180×126, 300×180, 150×220; значки 16 и 24 px. Для сравнения построителей используйте ссылки parametric/stencil/fixed-svg; примеры значков показаны отдельно. Статичный экспорт собственных контуров: [own-silhouettes.svg](own-silhouettes.svg).
- [React Flow, 50 блоков](http://127.0.0.1:15246/?mode=parametric&n=50). Начальный масштаб 0,05; приблизить колёсиком. Для удобного просмотра в консоли можно выполнить `await window.benchPreview()`.
- Параметры `mode=stencil|fixed-svg|react-icon|symbol|font|canvas2d|webgl`, `n=50|500|5000`, `cull=1`.

Короткий диагностический запуск (не сопоставим с полными результатами):

```sh
BENCH_REPEATS=1 BENCH_WARMUP_MS=100 BENCH_DURATION_MS=200 BENCH_FILTER=parametric:50:false npm run bench
```

Фильтр сопоставляется с подстрокой `mode:n:cull`: пример выше выбирает только 50 узлов без culling. Основной прогон: три повторения каждого из 27 сочетаний, прогрев 2 секунды и замер 4 секунды на повторение, порядок циклически сдвигается между раундами. Вместе с инициализацией занимает около десяти минут. Параметры `BENCH_REPEATS`, `BENCH_WARMUP_MS`, `BENCH_DURATION_MS` сохраняются в метаданные.

## Что сравнивается

Две разные оси:

1. **Контур целого блока:** `parametric` вычисляет пути из `(w,h)`; `stencil` один раз разбирает собственный XML и подставляет фиксированные/относительные координаты; `fixed-svg` растягивает собственный фиксированный `viewBox=180×126` с `preserveAspectRatio=none`. XML реализует небольшой собственный поднабор path-шаблонов; это **не** mxGraph/mxStencil runtime и не проверка совместимости с его библиотеками. На трёх размерах проверяется равенство XML и параметрической геометрии для шести типов.
2. **Доставка значка внутри обычной карточки:** собственный `react-icon` (memo React-компонент с SVG), `symbol` (одни defs + SVG use на каждом блоке), `font` (настоящий шрифт Font Awesome Free). Это отдельная нагрузка: размер и число SVG-путей, сложность глифов, форма карточки и размещение отличаются от полного контура. Разницу этих групп нельзя приписывать только способу доставки значка. Между React SVG и symbol используются одни собственные пути; глифы font являются ближайшими условными аналогами.

Все DOM-варианты работают внутри настоящего React Flow 12.12.0: редактируемый input, target/source Handle, выбор, перемещение, N−1 straight edges. Используется штатное неконтролируемое состояние `defaultNodes/defaultEdges`, чтобы React Flow сохранял измерения и изменения положения. `parametric` дополнительно проверяется с `onlyRenderVisibleElements=true`; по умолчанию параметр выключен.

Canvas2D и WebGL рисуют собственные те же контуры, тексты двух строк, цвета, метки и порты, N−1 рёбер в тех же позициях. Они используют атлас из шести заранее растеризованных карточек; WebGL рисует пакет текстурированных треугольников и линий. Это эскизы отрисовки: **нет** редактирования, клавиатурного управления, accessibility-дерева, модели React Flow, hit testing, drag/connect. Внутренние тексты и оформление близки, но не побайтно равны DOM. Их скорость не означает готовность заменить React Flow. Атлас с шестью повторяемыми строками оптимистичнее реальных тысяч уникальных названий и метрик.

## Методика и ограничения

Сетка `ceil(sqrt(N))`, шаг 244×172. Типы Person, Service, Database, Pooler, Router, Replicas чередуются; ширина 180/192/204 и высота 126/136; подпись типа, `capacity: 32`, `p99: 48 ms · 72%`, шесть цветов нагрева, метки переопределения и выделения у выбранных типов, по два порта. Последний неполный ряд остаётся неполным. Типовые подписи и метрики намеренно повторяются; это синтетическая нагрузка, не модель результатов эксперимента.

`firstReadyMs` начинается в bootstrap-script **до** динамического импорта общего production bundle, включая его загрузку/исполнение, создание данных/атласа и инициализацию renderer. Для DOM ждём `useNodesInitialized`; для font — загрузку шрифта; затем `document.fonts.ready` и два `requestAnimationFrame`. Это возможность выполнить отрисовку, **не** измерение первого фактического compositor paint. `navigationReadyMs` дополнительно включает навигацию HTML и ожидание барьера из Playwright. Общий bundle загружает React Flow даже для raster-эскизов; их старт не показывает минимально достижимую загрузку отдельного canvas-приложения.

На каждое повторение создаётся новый browser context: HTTP-кэш изолирован; браузер, процессы, файловый кэш ОС и loopback остаются прогретыми. Это не холодная сеть и не замер на пользовательском ноутбуке с обычными вкладками.

Масштаб меняется по прошедшему времени, по кривой 0,05 → 2 → 0,05 вокруг центра сцены. Фиксированное число кадров не используется. Сохраняются интервалы rAF, средний FPS по этим интервалам, p50/p95/max разрыва между кадрами и фактически достигнутый диапазон zoom. Скриншоты исключены из таймера. FPS характеризует доступность главного потока для rAF, не гарантирует показ каждого кадра compositor. При сильных задержках реализованный максимум масштаба может быть ниже 2.

`visibleSamples` — геометрическое число пересекающих viewport блоков на фиксированных масштабах; в каждой сцене центр остаётся занят. Это не число элементов в DOM и не измерение occlusion. `initialDom/finalDom`, `initialMountedNodes/finalMountedNodes`, `renderedEdges` дают фактические количества DOM. Отдельный пробный переход к zoom=2 после таймера сохраняет `detailDom/detailMountedNodes/detailVisibleNodes`, затем возвращает zoom=0,05; этот переход не включён в FPS. Начальный масштаб 0,05 помещает все 5000 узлов в viewport; поэтому culling не ускоряет этот начальный кадр, а при zoom может тратить время на массовое размонтирование и создание элементов. Один траекторный замер не покрывает все паттерны pan/zoom.

Метаданные содержат ОС, CPU, память, Node, точную версию/путь Chromium, разрешение, DPR, base commit, пакетные версии, параметры и WebGL vendor/renderer. Если WebGL использует программный renderer, результат относится к нему; вывод о скорости аппаратного GPU из такого замера делать нельзя. Headless Chromium ограничивает rAF примерно частотой 60 Hz; близкие результаты около этого предела не дают ранжирования. Память процесса/GPU, сетевой размер каждой альтернативы, Safari/Firefox, мобильные устройства, тысячи уникальных строк и полная доступность не измеряются.

В `summary.json` readiness/FPS/p95 — медианы по трём повторениям; также приведён p95 объединённых сырых интервалов. По трём повторениям нельзя оценивать доверительный интервал или универсальную производительность. Исходные интервалы сохранены для проверки, а не только итоговые числа.

Шрифт не модифицируется и не переименовывается. Его внешний вид отличается от собственных SVG, что явно учитывается при интерпретации сравнения.

Формы итогового прототипа: Person с перекрытием нижней трети головы телом (`d=min(0,38w;0,35h)`), Service с радиусом угла10px, Database с крышками высотой16px, Pooler с фиксированным внутренним отступом6px, Router с вписанной окружностью, Replicas со стопкой рамок. Порты Router лежат на окружности; его три строки центрированы и используют11px для параметра/метрики, чтобы поместиться в круг. У fixed-svg окружность растягивается в эллипс, что и демонстрирует ограничение фиксированного viewBox. `sourceSha256` фиксирует измеренные исходники, `installedVersions` — реальные версии установленных пакетов.

Поле `metadata.executable` содержит путь установленного Chromium, который возвращает API `chromium.executablePath()`, с заменой домашнего каталога на `~`. При стандартном `chromium.launch({headless:true})` Playwright запускает комплектный headless shell; это поле не является наблюдением пути запущенного процесса. `metadata.browser` получено через `browser.version()` у фактически запущенного браузера. Пользовательские аргументы запуска не добавлялись; стандартные аргументы Playwright остаются его внутренней реализацией.
