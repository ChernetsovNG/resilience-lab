# JSON-схемы документов

`model.schema.json`, `layout.schema.json` и `experiment.schema.json` описывают
текущие документы `*.model.json`, `*.layout.json` и `*.experiment.json`
по JSON Schema Draft 2020-12. `DocumentSchemas` генерирует структуру из
сериализаторов Kotlin через kotlinx-schema 0.6.0 и добавляет параметры каталога.
Файлы схем генерируются целиком; вручную их не редактируют.

Текущая версия модели — `schemaVersion: 6`; версии эксперимента и раскладки — 1.
У сервиса поле `scenario` содержит шаги `process` и `call`; схема проверяет
их поля, непустой список и параметры обработки по каталогу. Принадлежность
связи сервису проверяет компилятор. Модель прежней версии отвергается с ошибкой
`SCHEMA_VERSION`, миграций нет.

У клиента `load` заменяет `rate` и содержит только `points` — непустой массив объектов с величинами `time` и `rate`. Компилятор проверяет строгий порядок времени и неотрицательность значений точек. Профили сравниваются вариантами, перебор профиля сеткой не поддерживается. В каталоге массивы описывает вид параметра `ARRAY`, его `fields` задают поля элемента.

В модели один или несколько клиентов; каждый задаёт либо `load`, либо непустой массив `classes` с объектами `{ id, load }`. Идентификатор класса описывается строковым параметром `STRING` каталога; без `classes` используется класс `default`. Список классов переопределяется вариантом целиком, сеткой не перебирается. Поле `classes` у шага сценария и у связи `route` ограничивает их применение указанными классами; объявления классов и доступность маршрутов проверяет компилятор.

Из корня репозитория с JDK 25:

```sh
UPDATE_SCHEMAS=1 ./gradlew :core:test --tests 'resiliencelab.core.document.DocumentSchemasTest' --rerun
```

Без `UPDATE_SCHEMAS=1` тот же тест сравнивает файлы с результатом генерации.
Он входит в `./gradlew clean build`, который выполняет CI. Тесты также проверяют
примеры `examples/**`, неверные документы и сами схемы валидатором Draft 2020-12.

Схема модели выбирает параметры по типу блока или связи. Она проверяет их
обязательность, типы, единицы, варианты выбора, вложенные поля и диапазоны
обычных JSON-чисел. Необязательные параметры допускают `null`: ядро трактует
его как отсутствие значения и применяет значение по умолчанию из каталога.

Для величин вроде `60ms`, `120/s` и `1e1%` схема проверяет строковый тип и
единицы из `ParamDescriptor.units`. Числовые границы записаны в `description`
и аннотации `x-quantity`; проверяет их ядро. Аннотация содержит:

- `dimension` — имя `Dimension` из каталога;
- `units` — список `QuantityUnit` с полями `symbol`, `numerator` и `denominator`;
  каноническое значение равно числу перед единицей, умноженному на `numerator`
  и разделённому на `denominator`;
- `minimum`, `exclusiveMinimum`, `maximum` — заданные в `ParamDescriptor`
  границы в канонических единицах. Отсутствующая граница не записывается.

Канонические единицы: миллисекунды для `DURATION`, запросы за миллисекунду для
`RATE`, вероятность от 0 до 1 для `PROBABILITY`. Например, максимум `1.0`
для вероятности соответствует `100%`. Тест сверяет аннотации с каталогом.

Сериализатор Kotlin принимает также числа в кавычках в типизированных числовых
полях документов. Для совместимости схема допускает там строки, а их разбор
и числовые ограничения проверяет ядро. Это не относится к числовым параметрам
каталога: они требуют обычных JSON-чисел.

Ссылки, топологию и пути переопределений проверяет компилятор.
Значения `overrides` допускают любой JSON: их тип зависит от пути.
При появлении `grid` в классе документа его значения по путям также должны
допускать любой JSON. `$schema` в сами документы не добавляется: строгий кодек
отвергает неизвестные поля.
