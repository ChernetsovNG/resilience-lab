# Resilience Lab

Локальная лаборатория для исследования надёжности распределённых систем.
Соберите модель цепочки сервисов, задайте нагрузку и деградацию, сравните
настройки таймаутов и повторов до изменения работающей системы.

Текущая версия моделирует линейные синхронные вызовы: ограниченные пулы
обработчиков и очереди, таймауты, повторы с backoff/jitter и общий deadline.
Можно сравнить baseline и candidate с независимыми повторениями или выполнить
одномерную серию значений параметра (sweep). Результаты включают долю успешных
запросов, p95/p99 задержки, размножение нагрузки из-за повторов (amplification),
занятость обработчиков и длину очередей. Сценарии и результаты экспортируются в JSON.

Ядро на Kotlin и [Kotlin Simulation Library (KSL)](https://github.com/rossetti/KSL),
API на Spring Boot, браузерный интерфейс на React. Расчёт воспроизводится по
конфигурации и seed. Выводы зависят от допущений модели; калибровка по реальным
наблюдениям запланирована в следующих этапах.

## Быстрый старт: Docker Compose

Нужны Git и работающий Docker с Compose v2. JDK и Node.js на хосте не требуются.

```sh
git clone https://github.com/ChernetsovNG/resilience-lab.git
cd resilience-lab
docker compose up --build -d
```

Откройте [интерфейс](http://127.0.0.1:5173). Первая сборка загружает зависимости;
готовность backend можно проверить командой:

```sh
curl --fail http://127.0.0.1:8080/api/v1/health
```

Нажмите `Load retry storm example`, при необходимости измените параметры
`Baseline` или `Candidate`, затем нажмите `Run comparison` и дождитесь
`COMPLETED`. Прокрутите страницу к `Experiment result`: там появятся метрики
и графики.

Оба порта доступны только на `127.0.0.1`. Задания и результаты хранятся в памяти
backend: перед перезапуском сохраните нужные результаты через
`Download full result JSON`.
Остановить контейнеры:

```sh
docker compose down
```

## Запуск из исходников: Gradle и npm

Нужны JDK 25 и Node.js версии из [web/.nvmrc](web/.nvmrc) с комплектным npm.
Для выбора версии Node.js в примере используется установленный fnm или nvm.
Gradle устанавливать отдельно не нужно: используется wrapper репозитория.
Команды ниже выполняются в том же клонированном репозитории, после остановки
Compose. Порты `8080` и `5173` должны быть свободны.

В первом терминале, из корня репозитория, запустите API:

```sh
./gradlew :apps:server:bootRun
```

Во втором терминале перейдите из корня в `web`, установите Node.js через fnm
и запустите интерфейс:

```sh
cd web
fnm install
fnm use
npm ci
npm run dev
```

При использовании nvm замените `fnm install` и `fnm use` на `nvm install` и
`nvm use`. Оба менеджера читают версию из `.nvmrc`.

Интерфейс доступен по адресу [http://localhost:5173](http://localhost:5173).
Vite передаёт запросы `/api` локальному backend на `127.0.0.1:8080`.
Проверка готовности и запуск эксперимента такие же, как для Compose.
Для остановки нажмите `Ctrl+C` в обоих терминалах.

## Пример CLI

Для расчёта без браузера нужен только JDK 25. Из корня репозитория:

```sh
./gradlew :apps:cli:installDist
apps/cli/build/install/cli/bin/cli validate examples/retry-storm.json
apps/cli/build/install/cli/bin/cli run examples/retry-storm.json > result.json
```

[Пример retry storm](examples/retry-storm.json) сравнивает три попытки на связи
с одной при замедлении конечного сервиса. `validate` проверяет конфигурацию;
`run` сохраняет в `result.json` один JSON-документ с конфигурацией и численными
результатами. Диагностика идёт в stderr. Установленный launcher позволяет
получить чистый JSON без служебного вывода Gradle.
