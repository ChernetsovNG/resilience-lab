# Resilience Lab

Локальная лаборатория для исследования надёжности распределённых систем.
Соберите модель цепочки сервисов, задайте нагрузку и деградацию, сравните
настройки таймаутов и повторов до изменения работающей системы.

Текущая версия моделирует линейные синхронные вызовы: ограниченные пулы
обработчиков и очереди, таймауты, повторы с backoff/jitter и общий deadline.
Модель, раскладка и эксперимент — JSON-файлы рабочей области; варианты
эксперимента переопределяют параметры модели и сравниваются на независимых
повторениях. Результаты включают долю успешных запросов, p95/p99 задержки и
размножение нагрузки из-за повторов (amplification); прогоны сохраняются в
`.results/`.

Ядро на Kotlin и [Kotlin Simulation Library (KSL)](https://github.com/rossetti/KSL),
API на Spring Boot, браузерный интерфейс на React. Расчёт воспроизводится по
конфигурации и seed. Выводы зависят от допущений модели; калибровка по реальным
наблюдениям запланирована в следующих этапах.

## Быстрый старт: Docker Compose

Нужны Git и работающий Docker с Compose v2. JDK и Node.js на хосте не требуются.

```sh
git clone https://github.com/ChernetsovNG/resilience-lab.git
cd resilience-lab
docker compose up --build -d
```

Откройте [интерфейс](http://127.0.0.1:5173). Первая сборка загружает зависимости;
готовность backend можно проверить командой:

```sh
curl --fail http://127.0.0.1:8080/api/v1/health
```

В списке `Model` выберите `retry-storm/retry-storm`, затем в `Experiment` —
`retry-storm/retry-storm.experiment.json`. Список экспериментов содержит только
вопросы к выбранной модели. У `checkout/checkout` их два: сравнение вариантов
и перебор timeout × attempts. Последние открытые модель и эксперимент
запоминаются в браузере.
Выберите блок или связь на схеме, измените
параметр в инспекторе справа, нажмите `Save`, затем `Run` и дождитесь
`COMPLETED`: сводка по вариантам появится в панели внизу. Модель правится на
первой вкладке под схемой, `Model`. На вкладке варианта правка создаёт
переопределение в эксперименте; `Use model value` возвращает значение модели.
Переопределения отмечены в инспекторе и значком на схеме. Кнопки добавления,
копирования и удаления вариантов, их идентификатор и подпись находятся в
инспекторе. Кнопка `Run settings` в верхней панели открывает параметры прогона и
отказы для всех вариантов. Все эти правки поддерживают undo/redo и сохраняются
кнопкой `Save`.

Оба порта доступны только на `127.0.0.1`. Compose монтирует `./examples` в
`/workspace` на запись: изменения документов, `.workspace.lock` и `.results/`
остаются в каталоге хоста после `docker compose down` и перезапуска. Другой
каталог задаётся переменной `RESILIENCE_LAB_WORKSPACE`. На Linux создайте его
заранее и дайте выбранным ниже UID/GID право записи.

Для своей схемы выберите «Файл → Новая модель» и укажите имя. Откроется пустой
холст с подсказкой «Добавьте клиента из палитры». Вместе с моделью сохраняются
раскладка и эксперимент с одним вариантом `baseline` и 10 повторениями.
Пока клиента нет, `Run` недоступен; вместо ошибок незавершённой схемы видна
подсказка. Добавьте блоки из палитры, соедините порты и задайте параметры.

«Новый эксперимент» создаёт ещё один вопрос к текущей модели с теми же моделью
и раскладкой, отдельными настройками прогона и одним вариантом `baseline`.
«Сохранить модель как» копирует модель, раскладки и все её эксперименты,
включает несохранённые правки текущих документов и открывает копию.
Эти действия и `Save` записывают файлы в рабочую область сервера: при настройках
Compose по умолчанию они появляются в `examples/<каталог>/` на хосте.

Для переноса на компьютер выберите «Файл → Экспорт»: браузер скачает модель,
раскладку, если она есть, и эксперимент отдельными каноническими JSON-файлами.
Несохранённые правки перед экспортом предлагается сохранить. Для переноса
обратно выберите «Файл → Импорт», укажите эти файлы и каталог назначения;
совпадение имён требует явного подтверждения замены. Экспорт не включает
`.results/`. Импорт нескольких файлов выполняется по одному: если запись
прервалась, сообщение перечисляет уже сохранённые документы.

Backend запускается от non-root UID/GID `1000:1000`. На Linux, если у вашего
пользователя другие идентификаторы, задайте их перед запуском:

```sh
RESILIENCE_LAB_UID=$(id -u) RESILIENCE_LAB_GID=$(id -g) docker compose up --build -d
```

Так созданные файлы будут принадлежать пользователю хоста. Docker Desktop на
Windows и macOS сам сопоставляет запись с пользователем хоста; обычно менять
эти переменные там не нужно.

На Docker Desktop и Colima `.workspace.lock` связывает процессы внутри Linux VM,
но не связывает процессы хоста и контейнера. Пока работает Compose, не запускайте
на хосте CLI или `./gradlew :apps:server:bootRun` с той же рабочей областью:
блокировка не сериализует их записи с backend. На native Linux блокировка между
хостом и контейнером действует.

Остановить контейнеры:

```sh
docker compose down
```

Команда удаляет только контейнеры этого Compose-проекта; образы, исходники и
каталог рабочей области остаются. Браузер обращается к same-origin `/api`, Nginx
передаёт запросы сервису `backend:8080`. Оба контейнера работают от non-root
пользователей; секреты и named volumes не используются.

## Запуск из исходников: Gradle и npm

Нужны JDK 25 и Node.js версии из [web/.nvmrc](web/.nvmrc) с комплектным npm.
Для выбора версии Node.js в примере используется установленный fnm или nvm.
Gradle устанавливать отдельно не нужно: используется wrapper репозитория.
Команды ниже выполняются в том же клонированном репозитории, после остановки
Compose. Порты `8080` и `5173` должны быть свободны.

В первом терминале, из корня репозитория, запустите API:

```sh
./gradlew :apps:server:bootRun
```

Рабочая область сервера по умолчанию — `examples/`; другой каталог задаётся
переменной `RESILIENCE_LAB_WORKSPACE` или аргументом
`--args='--resilience-lab.workspace=<каталог>'`. Новое API описано в
[спецификации OpenAPI](apps/server/openapi.json). Браузерный интерфейс
использует API этапа 1.

Во втором терминале перейдите из корня в `web`, установите Node.js через fnm
и запустите интерфейс:

```sh
cd web
fnm install
fnm use
npm ci
npm run dev
```

При использовании nvm замените `fnm install` и `fnm use` на `nvm install` и
`nvm use`. Оба менеджера читают версию из `.nvmrc`.

Интерфейс доступен по адресу [http://localhost:5173](http://localhost:5173).
Vite передаёт запросы `/api` локальному backend на `127.0.0.1:8080`.
Проверка готовности и запуск эксперимента такие же, как для Compose.
Для остановки нажмите `Ctrl+C` в обоих терминалах.

## Примеры

Рабочая область `examples/` содержит:

- [retry-storm](examples/retry-storm/) — короткое сравнение повторов и одной
  попытки при замедлении конечного сервиса; на нём работают основные E2E.
- [checkout](examples/checkout/) — оформление заказа через шлюз, сервис заказа,
  платёжный сервис и внешний PSP. Источники чисел и типичные допущения записаны
  в `notes`. `checkout.experiment.json` сравнивает четыре настройки, включая
  согласованные таймауты и увеличенный платёжный пул.
  `checkout-grid.experiment.json` перебирает timeout × attempts у baseline
  той же модели: отдельный эксперимент сохраняет настройки остальных вариантов.

В web выберите нужный путь `*.experiment.json` в списке `Experiment`, затем
нажмите `Run`. Для сетки выберите вкладку `Baseline` под схемой и `Map` в панели
результатов. Отдельной команды открытия примера нет. Числа checkout синтетические;
результаты показывают поведение этих допущений и требуют калибровки для реальной системы.

## Пример CLI

Для расчёта без браузера нужен только JDK 25. Из корня репозитория:

```sh
./gradlew :apps:cli:installDist
apps/cli/build/install/cli/bin/cli validate examples/retry-storm/retry-storm.experiment.json
apps/cli/build/install/cli/bin/cli run examples/retry-storm/retry-storm.experiment.json
apps/cli/build/install/cli/bin/cli validate examples/checkout/checkout.experiment.json
apps/cli/build/install/cli/bin/cli run examples/checkout/checkout.experiment.json
apps/cli/build/install/cli/bin/cli run examples/checkout/checkout-grid.experiment.json
apps/cli/build/install/cli/bin/cli catalog
apps/cli/build/install/cli/bin/cli schema model
```

[Пример retry storm](examples/retry-storm/) сравнивает три попытки на вызовах
с одной при замедлении конечного сервиса. `validate` проверяет модель и
эксперимент; `run` записывает результат в `.results/retry-storm/<прогон>/`
и печатает путь к нему и краткую сводку по вариантам. `catalog` печатает
каталог типов в stdout; `schema <model|layout|experiment>` — JSON-схему
соответствующего документа. Ход расчёта и диагностика идут в stderr.
Рабочая область CLI — текущий каталог; `run --workers N <эксперимент>`
задаёт число потоков расчёта.
